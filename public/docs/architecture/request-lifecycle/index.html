Request lifecycle

This page follows two requests through the host: a GET that runs a function and a POST that runs an action. Module names refer to files under host/src/. The two verbs in the example are bootstrapped JavaScript examples that a host with the JS runner deploys at startup when it runs with RESTACT_EXAMPLES=1 (as make run does).

The path in one picture

Section titled “The path in one picture”

A function call, step by step

Section titled “A function call, step by step”
  1. Router. build_router in lib.rs maps /v1/{*path} to handle_v1. Two middlewares in origin_guard.rs run first: the Host allowlist and the cross-origin check. A request timeout and in-flight cap apply to the whole request.
  2. Path split. handle_v1_inner splits the path at the last colon. With no colon, the request is on the data plane (data_plane.rs). With one, the left side is the object and the right side is the verb, optionally followed by /<property>.
  3. Authentication. authenticate_request in lib.rs walks the identity chain (trusted header, then OIDC through oidc.rs, then an HS256 token through auth.rs) and produces a principal. A restact.auth tracing span wraps the whole dispatch.
  4. Admission rules. The router rejects a mutation by an anonymous caller when authentication is configured. For a bare verb, GET means the function kind and POST the action kind.
  5. Invocation. invoke_op in invoke.rs hands the request to the executor on a blocking thread, behind a limiter that caps concurrently executing verbs. The request body or the ?input= query string becomes the verb’s input.
  6. Resolution. In wasm_exec.rs, WasmtimeExecutor::invoke asks registry.rs to resolve the route: the object path is matched against deployed patterns with an ancestor walk, and the deepest match wins. Among patterns at one level, the one with a literal at the first differing segment from the left wins. A kind mismatch is 405.
  7. Quota. quota.rs checks the tenant’s fuel and call counters. Over quota returns 429.
  8. Policy. invoke_core checks the verb’s execute policy (policy.rs) for the principal. Anonymous callers who fail get 401, named callers 403. A verb deployed to run as its owner switches principal after this check.
  9. Instantiation. The verb’s component, compiled once and cached by compile_cache.rs, is instantiated with a fresh store carrying fuel, an epoch deadline and a memory limiter. Script verbs instantiate the shared runner and pass it the stored source with the input.
  10. Capabilities. While the verb runs, each host call goes through the linked interfaces. object.get consults store.rs through the same read rules as the data plane. compose.invoke re-enters invoke_core for the callee with the shared budget. A function’s attempt to write returns 403.
  11. Response. Output bytes return to invoke_op. For a function it computes an ETag, honours If-None-Match with 304, and adds Cache-Control: private, no-cache and Vary: Authorization. Errors are mapped to RFC 9457 problem documents by http_util.rs.

An action call, step by step

Section titled “An action call, step by step”

The first five steps match. The differences:

  • invoke_action first handles an Idempotency-Key. A repeated key from the same authenticated caller replays the original result instead of running again. A claim on a key is released if the request is dropped.
  • The executor runs the action under the same checks. Writes to the verb’s own object are buffered and merged into the store only if the invocation succeeds. Writes to other objects commit at the call, unless the server runs at the atomic-invocation consistency level, which commits the whole write set together.
  • After the response is decided, a data change the verb made can trigger lifecycle hooks and event delivery. These run as separate invocations under their registrant’s authority and do not alter the response.
  • An action POST that sends Prefer: respond-async returns 202 with Location: /operations/{id}, which the client polls.

With process isolation

Section titled “With process isolation”

With RESTACT_ISOLATION=process, step 5 changes: process_exec.rs starts a worker subprocess, passes it the principal and the input, and reads back the output. The worker opens the same durable store and applies the same resolution, policy and limits. The Executor trait in executors.rs is the seam that lets both backends return the same results.
