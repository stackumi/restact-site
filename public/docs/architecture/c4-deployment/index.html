Deployment

This diagram shows how the reference container image and the compose files lay the system out at run time.

What you are looking at

Section titled “What you are looking at”
  • A multi-stage Dockerfile builds the host, the example verbs and both runners into a slim image that runs as a non-root user. It binds 0.0.0.0:8080 inside the container, with localhost as the allowed host name, and keeps durable state in a /data volume.
  • The PostgreSQL compose file: two host nodes share one PostgreSQL database. This is the active-active layout: the nodes are stateless, and a load balancer in front of them can send any request to either.
  • The OpenBao compose file: a host reads credentials from a secrets backend through a mounted token. This is the layout egress mediation requires.

The services are taken from those files, so the diagram follows them when they change. The generated model is docs/architecture/c4/workspace.dsl, and How the diagrams are made lists the rule for each node.

Reading it

Section titled “Reading it”

A single node needs only the image and a volume. The other two files add a database or a secrets store. For the options that wire them up, see Configuration, and for running the image, Run with Docker. The Production checklist lists what to review before you expose a node.
