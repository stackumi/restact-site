Errors and status codes

restactd reports errors as RFC 9457 problem documents with two extension members, restact_code and restact_verb. This page lists the response shape, every status code the API returns, and the restact_code values you can match on.

Response shape

Section titled “Response shape”

An error response has the content type application/problem+json.

MemberMeaning
typeAlways about:blank.
titleThe standard reason phrase for status.
statusThe HTTP status code.
detailA human-readable explanation. Safe to show to a user; it never echoes secrets.
restact_codeA stable machine-readable code. Match on this, not on detail.
restact_verbThe part of the route from the colon onward, such as :summarize. Empty when the request named no verb.

Two headers can come with an error. A 401 carries WWW-Authenticate: Bearer. A 408 or a compute-budget 429 carries Retry-After: 1, an advisory number of seconds. A quota 429 carries the seconds until the quota window rolls over, and no Retry-After when waiting will not help (a lifetime cap or the storage quota).

A request that the web framework rejects before routing, such as a POST /v1/modules without the required verb query parameter, returns a short text/plain 400 instead of a problem document.

Status codes

Section titled “Status codes”
StatusWhenTypical restact_code
400The request is malformed: an invalid component (not a component, or one without the invoke export), a body that is not a JSON object, a bad parameter, a malformed Host header, an If-Match or If-None-Match on a request whose route cannot evaluate it (a write an accessor verb serves, a verb-route action, an event-stream subscribe) or a malformed one, an invalid call graph, or a function verb that imports a capability with side effects.invalid-input, invalid-component, invalid-call-graph, forbidden-side-effect
401The request needs authentication and has none, or the bearer token is invalid. Once any authentication is configured, an anonymous caller cannot deploy or write.unauthorized
403The caller is authenticated but not allowed: the object or verb policy refuses, a property write is refused, the verb did not declare the call it made, an upload imports a capability that is not granted or that the host does not provide, the Host header is not on the allowlist, or a cross-origin browser request is not permitted.forbidden, not-declared, disallowed-import, forbidden-side-effect, delegation-bound
404No verb, object, property, operation or route matches.not-found
405The method does not fit the verb: POST to a function, GET to an action, or any other method on a verb route.method-not-allowed
408The call ran past its wall-clock limit, or the request timed out.timeout
409A conflict with current state: an Idempotency-Key that is still in progress, a write to a final property that is already set, a verb deployed on an object that does not exist under strict object binding, or a clash with the verb already deployed.conflict, property-final, object-binding
412A precondition failed: the ETag in If-Match is stale, or If-None-Match: * found the resource already exists.precondition-failed
413The input is over a size limit: a module over 10 MiB, an object or value over the per-object cap, a blob over RESTACT_MAX_BLOB_BYTES, or a published event over its data cap or an invocation’s published total.module-too-large, object-too-large
415The upload names a source language the host has no runtime for, or, on a path no :update accessor serves, a non-empty data-plane PUT body carries no usable Content-Type (none, blank, or not a single type/subtype, or has a comma anywhere in it); more than one Content-Type line is refused whatever the body.unsupported-language, invalid-input
422The input is understood but refused: uploaded source that fails its syntax check, or an error a verb returns for bad input. A guest error with an unrecognised code also maps here.invalid-source, invalid-input, script-error
429A budget or quota is used up: the fuel budget, a per-tenant quota, a rate limit, or the concurrency cap of a mediated outbound call.cpu-budget, quota, quota-exceeded, egress-busy
500The host or the verb failed in a way the caller did not cause: a trap, a script runtime fault, a store write error, or a stored verb that no longer links against this host (an interface it imports was removed or changed since it was deployed). The verb stays listed; redeploy it against this host or delete it.trap, script-runtime, store-error, verb-unlinkable
501The host does not support something the request needs, such as a feature that is switched off.unsupported-feature, unsupported-consistency
502An outbound call or model completion reached an upstream that failed or redirected.egress-upstream-error, egress-redirect-refused, llm-upstream-error
503The host cannot serve the request now: the store is unreachable, too many asynchronous operations or event subscriptions are open, an uploaded source’s syntax check ran past its window (Retry-After; nothing was stored), or a feature needs configuration that is missing, such as a token issuer.unavailable
507The call exceeded its memory limit.memory-limit
508A composed call formed a cycle, or went deeper or wider than the host allows.composition-cycle

Success and cache responses are not errors, but you will see them next to these: 200, 201, 202 (an action POST with Prefer: respond-async; poll the Location: /operations/{id}), 204, and 304 for a matching If-None-Match.

Resource limits

Section titled “Resource limits”

A verb runs under three limits. Each has its own status so a client can tell which one it hit.

LimitStatusrestact_code
Wall-clock time408timeout
Fuel (compute)429cpu-budget
Memory507memory-limit

Composed calls share one budget, so a callee can exhaust the caller’s fuel. The defaults and the operator ceilings are in Capabilities and budgets.

Errors from outbound calls

Section titled “Errors from outbound calls”

The mediated outbound call and the llm interface add their own codes. They fall into four groups.

  • A 403 means the call was refused by policy: the destination is not on the allowlist (egress-not-allowed), resolves to a blocked address (egress-blocked-address), or a connector or secret is not governed or not readable by the caller (egress-denied, egress-connector-ungoverned, secret-denied, llm-model-not-allowed).
  • A 422 means the connector or request is invalid (egress-connector-invalid, egress-method-refused, connector-kind-mismatch, llm-provider-unsupported, budget-unconfigured).
  • A 413, 429 or 502 means a bound was hit or the upstream failed (egress-bounds-exceeded, egress-busy, llm-request-too-large, llm-calls-exceeded, budget-exhausted, egress-upstream-error).
  • A 503 means the secret could not be resolved or the call is not available in a worker (secret-unresolvable, egress-unavailable-in-worker, typed-call-unavailable-under-isolation).

See Outbound calls and secrets.

Errors from your own verbs

Section titled “Errors from your own verbs”

A verb returns an error as an invocation-error with a code and a message; see WIT interfaces. If the code is one of the reserved codes above, the host uses that code’s status. Any other code becomes a 422 with that code in restact_code, so a verb can report its own failures, such as out-of-stock, without a new status.
