Feature flags in discovery

A host lists the optional features it supports as strings in service.features of its discovery document. A client reads the list and uses only what it finds there; it never assumes a feature by trial.

A host with no configuration advertises 49 tokens, and 50 when a scripting runner is built, because source-languages joins the list. Rows marked default are among them. Rows marked opt-in appear only after the operator sets what the third column names, and the token disappears again when it is unset. The REST:ACT specification holds the registry of feature tokens and their normative meaning. See Discovery and optional features for how clients use them.

Related discovery fields that are not feature tokens: consistency, objectBinding, accessorDispatch, lifecycleHooks, acceptedSourceLanguages and openapi.
