Configuration

The reference host is configured entirely through environment variables. This document lists every variable, explains the security posture, and gives a production checklist. The variables the restact client reads are in the command line reference.

Environment variables

Absent → the fully generated document. A missing file or a syntax error is fatal at startup. See openapi/examples/library.openapi.yaml for a worked example.

Clustering / horizontal scaling (PostgreSQL)

Section titled “Clustering / horizontal scaling (PostgreSQL)”

The default host is single-node — all shared state lives in-process. Setting RESTACT_DATABASE_URL (on a binary built with the postgres feature: cargo build -p restactd --features postgres) points N equal nodes at one PostgreSQL so object writes (advisory-lock-serialized — no lost updates), schedules (fire once cluster-wide, with failover), idempotency + async operations, quota, and SSE/events all span the cluster. When unset, the host uses the filesystem or in-memory store; PostgreSQL is a secondary backend, not a replacement. It is a storage/deployment choice and is not advertised in discovery.

Connection security is fail-safe (no silent plaintext). The DB connection defaults to sslmode=require; the downgradeable modes (disable/allow/prefer) are refused unless RESTACT_PG_ALLOW_PLAINTEXT=1 (the loopback/dev opt-out — a throwaway postgres:16 has no TLS). Use sslmode=verify-full (with a CA) for MITM protection in production.

Degradation on a DB error. The idempotency claim fails closed (409), and the cross-node quota read fails open (logged as restact.pg.quota read_failed fail_open=true). The prune is leader-elected: one node per tick, via pg_try_advisory_lock.

The released -full image and a source build with WITH_PG=true (make docker-build-pg) include the PostgreSQL backend, and scripts/postgres-test.sh verifies the backend.

Postgres has no analogue of the in-memory FIFO caps. The event_log is bounded on every insert, in bytes and in rows, and a background prune (leader-elected — one node per tick) bounds the idempotency and operations tables; the RESTACT_PG_* knobs below tune them and the connection pools. Set the event log bounds to the same values on every node.

RESTACT_PG_POOL_SIZE16Query connection pool size (per node).

RESTACT_PG_RESYNC_INTERVAL_SECS60Whole seconds, 1 to 86400. Process isolation composes with PostgreSQL. RESTACT_ISOLATION=process needs no data dir under PG: the worker subprocess inherits RESTACT_DATABASE_URL and shares the same database (a single lazy connection), so its object.set/set-at commits serialize cluster-wide through the same advisory locks; the parent owns the prune loop, the event transport and the quota debit. Size max_connections accordingly (see the checklist).

Authentication & authorization

Section titled “Authentication & authorization”

restact resolves the caller’s identity through an ordered chain: a trusted forwarded-identity header (if configured) is consulted first, then a cryptographically-verified OIDC/JWKS bearer JWT (if configured), then an Authorization: Bearer HS256 token, then the anonymous fallback. The first source that yields a non-anonymous principal wins.

VariableDefaultEffect
RESTACT_TRUSTED_IDENTITY_HEADER(unset)Enable switch for trusted forwarded identity (no signature check). Name of the request header carrying the subject (an email or user id) → Principal.subject. Trusted at face value; see the caveat below. Absent → feature off; set but blank or not valid Unicode refuses boot.
RESTACT_TRUSTED_ROLES_HEADER(unset)Optional. Header with comma/whitespace-separated roles → Principal.roles. Needs RESTACT_TRUSTED_IDENTITY_HEADER; set without it, boot is refused.
RESTACT_TRUSTED_SCOPES_HEADER(unset)Optional. Header with whitespace-separated scopes → Principal.scopes. Needs RESTACT_TRUSTED_IDENTITY_HEADER; set without it, boot is refused.
RESTACT_TRUSTED_GROUPS_HEADER(unset)Optional. Header with comma/whitespace-separated groups → Principal.groups (for the group: policy matcher). Needs RESTACT_TRUSTED_IDENTITY_HEADER; set without it, boot is refused.
RESTACT_RESERVED_SUBJECT_PREFIXES(unset)Comma-separated subject prefixes (entries trimmed, empty ones ignored), for example agent:. A subject from OIDC or the trusted identity header that starts with one is refused 401; an HS256 bearer or sub-token may use it, which is how your own services authenticate inside the namespace. Combined with prefixes an embedder reserves through HostBuilder::reserve_subject_prefix; neither source can remove the other’s, and RESTACT_EXTERNAL_SUBJECT_ALLOW cannot lower them. End each prefix with its separator (agent:, not agent). An entry holding whitespace or a control character refuses boot (fatal:).
RESTACT_EXTERNAL_SUBJECT_ALLOW(unset)Comma-separated tokens from colon and whitespace that relax the default character rules for subjects from OIDC and the trusted identity header. By default such a subject is refused 401 when it contains : (or the fullwidth colon U+FF1A), whitespace, or a Unicode format character. colon lifts the : rule (set it when your IdP issues colon subjects: GitHub Actions, GitLab CI or Kubernetes workload tokens, SPIFFE, Tailscale tsidp, Keycloak federation without import); whitespace lifts the whitespace rule. Control characters and format characters are always refused, and reserved prefixes still apply. An unknown token refuses boot. The boot log states the rules in force and each refusal logs its mechanism and rule class (never the subject).
RESTACT_OIDC_ISSUER(unset)Expected iss claim. One of the three variables that enable OIDC/JWKS verification (RESTACT_OIDC_ISSUER, RESTACT_OIDC_JWKS_URL, RESTACT_OIDC_AUDIENCE); all three are required. Setting any RESTACT_OIDC_* variable, even to an empty value, without all three of issuer, JWKS URL and audience non-blank refuses boot and names the missing variables, so a host never starts with OIDC silently off. Confirm the boot line auth: OIDC/JWKS verification enabled ….
RESTACT_OIDC_JWKS_URL(unset)URL of the issuer’s JWKS (signing keys). It must be https://: a remote plaintext URL refuses boot, because the JWKS is the trust root and a plaintext fetch can be tampered with. Plain http:// is accepted only to a loopback host (localhost, any 127.0.0.0/8 address, or ::1) for dev and test, and a URL that does not parse refuses boot. Redirects are not followed, so this must be the final URL. The key set is fetched with a size cap and cached (TTL plus a throttled refetch on an unknown kid); a failed fetch rejects tokens.
RESTACT_OIDC_AUDIENCE(unset)Expected aud claim. Audience validation is mandatory — there is no way to disable it.
RESTACT_OIDC_JWT_HEADERAuthorizationOptional. Request header carrying the token (a leading Bearer is stripped). An invalid header name refuses boot. Custom headers (e.g. a proxy-forwarded X-Id-Token) carry the raw JWT.
RESTACT_OIDC_SUBJECT_CLAIMsubOptional. Claim mapped to Principal.subject.
RESTACT_OIDC_JWKS_TTL_SECS3600Optional. JWKS cache TTL in seconds. A value that is not a whole number (empty included) refuses boot.
RESTACT_JWT_SECRET(unset)Enables HS256 bearer-token auth and the owner/public policy. Absent → anonymous-only (see warning below); set but empty, blank, not valid Unicode or shorter than 32 bytes (the HS256 hash size; counted in bytes) refuses boot. Once ANY auth is configured (this, the RESTACT_OIDC_* set or RESTACT_TRUSTED_IDENTITY_HEADER), an anonymous caller may not mutate — deploy, :verb management writes and data-plane PUT/PATCH/DELETE answer 401 (so an unauthenticated caller cannot match the owner matcher of an anonymously-owned or bootstrapped resource and seize it); reads and execute-policy-gated action invocation stay open. The subject anonymous is reserved: an absent $owner resolves to anonymous, so a credential carrying that exact, case-sensitive subject (an HS256 bearer or sub-token, an OIDC token, the trusted identity header, the remote MCP facet, an exchange actor_token) would own every ownerless object and pass the anonymous-mutation rule above; it is refused 401 on every path (and a stored delegation grant whose subject is anonymous never yields a delegated principal), whether or not delegation is on. The bearer and OIDC refusals carry the same body as an invalid credential on that path; the trusted-header refusal carries its own plain “credential is not accepted” detail. Near-misses such as Anonymous stay ordinary subjects. A subject containing a control character (NUL, newline, tab, DEL, C1) is refused 401 on every ordinary path, HS256 included, so that every store treats a subject alike. Idempotency replay and async-operation ownership are honored only for an authenticated caller: anonymous callers share one label, so an anonymous Idempotency-Key is ignored and its operation ids carry an unguessable random suffix. restactd token mint reads it too, with the same checks, to sign tokens.

OIDC/JWKS verification cryptographically verifies a forwarded RS256/ES256 JWT against the issuer’s published keys — the production alternative to trusting a header (you switch from a demo to real verification by configuration alone). The verification algorithm is pinned from the JWK (RSA→RS256, EC P-256→ES256), never from the token header, so an alg-confusion or alg:none token is rejected; iss/aud/exp/nbf/iat are all validated, fail-closed (including a zero/unavailable wall clock). When both OIDC and HS256 are configured on the same header, OIDC wins on success. Only a token that is not an OIDC token (not a JWT, or no kid) falls through to HS256, so HS256 service tokens still authenticate; a token that fails OIDC verification (bad signature, unknown kid, expired, wrong aud, JWKS unreachable) is 401. A present-but-invalid token never silently becomes anonymous. Like the other auth modes this is deployment config — it is not advertised in discovery and is not a conformance feature. Validate a deployment with scripts/oidc-test.sh (make oidc-test).

Operational notes.

  • Key rotation window. A JWKS refetch (triggered by an unknown kid) is throttled to at most once per ~60s to bound a bogus-kid flood. So for up to ~60s after the issuer rotates signing keys, a token signed with the brand-new key may intermittently 401 until the cache refreshes — it fails closed and self-heals. Keep RESTACT_OIDC_JWKS_TTL_SECS comfortably below your issuer’s key-rotation cadence.
  • Blocking pool. OIDC verification runs on the same blocking pool as verb execution; keep RESTACT_MAX_INFLIGHT enabled (the default) — it bounds how many concurrent verifications (and thus pool threads) an OIDC-header flood can consume.
  • Outbound egress. With OIDC enabled, restact makes outbound HTTPS to RESTACT_OIDC_JWKS_URL (the IdP’s JWKS endpoint) — a new egress requirement for a host that otherwise makes no outbound calls. In egress-restricted deployments (k8s NetworkPolicy, locked-down containers, air-gapped), allow egress to the issuer host on 443; a blocked JWKS fetch fails closed (all OIDC tokens → 401). The Mozilla CA roots are compiled into the binary (webpki-roots), so no OS CA store is required.
  • One identity source per subject namespace. Principals from OIDC and HS256 share a flat subject namespace (no issuer prefix), so an HS256 token with sub:"alice" and an OIDC token for alice are the same principal for ownership/ACLs. If you enable both, ensure their subject namespaces don’t overlap (or rely on one source); a leaked HS256 secret could otherwise impersonate an OIDC subject. To keep a namespace for subjects you mint yourself over HS256, list its prefix in RESTACT_RESERVED_SUBJECT_PREFIXES: OIDC and the trusted header can then never produce it. Independently, a subject from those two sources may not contain :, whitespace or a format character unless RESTACT_EXTERNAL_SUBJECT_ALLOW relaxes the first two. Issuers that put a colon in sub on purpose (GitHub Actions, GitLab CI, Kubernetes service accounts, SPIFFE, tsidp) need RESTACT_EXTERNAL_SUBJECT_ALLOW=colon. Plain overlapping names such as alice still rely on the one-source rule.

Caution

Trusted-header mode trusts the header at face value — only enable it when restact is exclusively reachable through a trusted proxy that sets this header and strips any client-supplied copy. With it on, restact performs no signature check (OIDC/JWKS verification does that): if a client can reach restact directly, it can spoof any identity by sending the header. The proxy authenticates the user (Cloudflare Access, oauth2-proxy, Authelia, Keycloak, Tailscale Serve, Traefik forward-auth, …) and forwards the result; restact stays vendor-neutral. When both a trusted header and a bearer token are present, the trusted header wins (precedence above); an absent/empty header falls through to the bearer path, so service tokens still authenticate there. On startup the host logs which header is trusted (auth: trusted identity header '<name>' enabled …) so the mode is never a silent surprise.

An operator plugs in whatever header their proxy emits, e.g. Cf-Access-Authenticated-User-Email (Cloudflare Access), X-Auth-Request-Email (oauth2-proxy), or Remote-User (Authelia).

Verb policy matchers. A verb’s policy (GET/PUT /v1/<obj>:<verb>/policy) gates read/execute/write, each an OR-list of canonical matchers — public, owner, sub:<id>, role:<r>, group:<g>, scope:<s>, claim:<k>=<v> (the same vocabulary as per-property ACLs and object $policy). A single matcher may be written/read as a bare string; a list is a JSON array. A verb uploaded through POST /v1/modules starts owner-only for every action (see Deploy a verb); exec=public opens execute.

Isolation

Section titled “Isolation”
VariableDefaultEffect
RESTACT_ISOLATION(unset)Set to process for per-request worker-process isolation; only an unset variable runs in-process, and any other value, an empty one included, refuses to start (exit 1) naming the variable. Needs RESTACT_DATA_DIR or RESTACT_DATABASE_URL (the worker re-opens whichever durable backend the parent uses); without one the host refuses to start (exit 1). Under process isolation discovery omits targeted-invalidation, because a worker’s reads never reach the parent.
RESTACT_WORKER_TIMEOUT_MS30000Kill deadline for a process-isolation worker. The worker itself stops running wasm a little earlier (5% of the value, between 100 ms and 1 s, never more than half of it), so a run cut off at its time limit is still metered and charged to its caller; once that moment has passed no further verb, composed call or hook starts. A worker killed after it wrote its whole response is metered from that response; one killed before that reports nothing, so hook compute from that run is lost and the caller is charged the verb’s whole fuel limit.
RESTACT_COMPILE_CACHE_DIR$XDG_CACHE_HOME/restactd (when that is an absolute path), else $HOME/.cache/restactdWhere compiled verb components are cached between runs and shared with process-isolation workers. Each entry is sealed with an HMAC and checked before it is loaded; an entry that fails the check is recompiled, never loaded. off (any letter case) disables the disk cache, and then every worker compiles each component it loads. The directory must be owned by the server’s user and not group- or world-writable, or the cache is disabled with a warning. A root that is a symbolic link turns the cache off with a warning. With none of the directory variable, an absolute XDG_CACHE_HOME and HOME set, the cache is off and the host logs a boot warning. wasmtime’s own ~/.cache/wasmtime and ~/.config/wasmtime/config.toml are not used.
RESTACT_COMPILE_CACHE_KEY_FILE<cache dir>/key (generated, mode 0600)The HMAC key for cache entries: a file of 32 to 4096 bytes, used as-is. Point it at a read-only secret on a different filesystem from the cache, so that someone who can write the cache cannot forge entries. A set but missing, unreadable or wrongly sized file refuses boot.
RESTACT_COMPILE_CACHE_MAX_BYTES2147483648 (2 GiB)Size cap for the running engine’s cache entries, enforced at boot by deleting the oldest entries down to three quarters of the cap. The same sweep removes the directories of other engine configurations whose newest entry is over 30 days old. A value that is not a number falls back to the default, with a boot warning.

Quotas & rate limiting

Section titled “Quotas & rate limiting”
VariableDefaultEffect
RESTACT_QUOTA_FUEL(unset)Per-tenant cumulative compute (fuel) cap. Enforced on both backends — fuel is debited under process isolation too. Every deploy-time validation is charged to the caller, whatever the outcome: a deploy, a code replace, a rollback, or a policy write that re-validates the stored code is debited the flat deploy cost, or the fuel the validation consumed when that is more, whether it succeeds or is refused (bad component, source that does not compile, a validation timeout, a failed precondition or a write refusal decided after the upload was checked). A request refused before any validation runs costs nothing: no credential (401), over quota (429), a malformed request or precondition header (400), an unsupported language (415), a bad verb name, accessor kind or call graph, a source over the size cap, a body over the module limit (413). A refusal decided after the upload was validated (403 on a verb the caller may not write, 412 on a failed precondition) is charged.
RESTACT_QUOTA_CALLS(unset)Per-tenant cumulative invocation cap.
RESTACT_QUOTA_WINDOW_SECS(unset)Accounting window for the fuel/calls quotas: a tenant’s tally expires this many seconds after its window opened, turning the lifetime circuit breaker into a per-window budget. 86400 gives each tenant a rolling daily budget measured from its first debit (each tenant rolls over independently — not a global midnight reset), and a full-budget burst at a window boundary can briefly reach ~2× the cap (the soft-cap overshoot semantics). Filter pitfalls

Section titled “Filter pitfalls”
  • EnvFilter reads an unrecognised value as a target directive, not a level. RESTACT_LOG=inf (a typo for info) enables only a target literally named inf and leaves no global default, so the access line disappears with no diagnostic while the host looks healthy. A genuinely invalid directive (for example =debug) refuses to boot with fatal: telemetry initialization failed: invalid RESTACT_LOG filter: … and exit code 1.
  • A directive that turns a target off also silences the boot refusals that log on it. The egress interlock refusal is on restact.egress; the database URL, lock-establishment and governed-creation refusals are on restact.boot; the secrets-backend refusals are on restact.secrets. For example RESTACT_LOG=off or info,restact.egress=off makes the process exit 1 with no reason on stderr. The default filter never does this. The plaintext-OpenBao warning: is a WARN event on restact.secrets, so RESTACT_LOG=error hides it while the ERROR-level refusals keep printing.
  • Target directives are prefix matches. RESTACT_LOG=info,restact.guest=off, the natural way to quiet the verb log, also drops every restact.guest.audit.* line (the egress, llm and secrets audit lines), every restact.guest.wasm line (host diagnostics that can carry a caller-chosen object path) and every restact.guest.boot line. To keep them, add the sub-targets back: …,restact.guest=off,restact.guest.audit=info,restact.guest.wasm=warn,restact.guest.boot=warn.
  • restact.invoke, restact.worker and restact.auth each name both an event target and a span. A directive selects the event target only, so RESTACT_LOG=restact.invoke=debug does not affect the span, and RESTACT_LOG=restact.auth=off silences the OIDC-rejection event but not the span.
  • An explicit RESTACT_LOG=info also admits third-party session logs such as rmcp’s, and the level gates the restact.sse event (debug) and the restact.worker event (warn) as well as the access line.

Three boot refusals, each checked before any exporter is built, each exiting non-zero with a fatal: line that names the variable and never prints its value, and each applying only when an exporter would be built (an endpoint set, OTEL_SDK_DISABLED not true):

  • OTEL_EXPORTER_OTLP_HEADERS, or any of its per-signal spellings (…_TRACES_HEADERS, …_METRICS_HEADERS, …_LOGS_HEADERS), is set. The exporter library would send those headers on every request, so the host refuses rather than carry a backend credential — that belongs on the collector.
  • An endpoint variable (the base URL or any per-signal one) carries URL userinfo (http://user:password@…), or a query string or fragment (?… / #…). An endpoint is a plain URL; no credential may ride anywhere in it.
  • An endpoint variable’s scheme is neither http:// nor https://. Enforced on the base URL and every per-signal variable.

RESTACT_LOG does not gate export. RESTACT_LOG is attached to the stderr layer ONLY. The OTel trace/log layers carry their OWN fixed filter: an allowlist of the host’s own targets plus a fixed INFO level ceiling, independent of RESTACT_LOG in EITHER direction. Under RESTACT_LOG=warn, the INFO http.server/restact.auth request spans still export, and an admitted log record still carries its trace/span ids and attributes exactly as at the default filter (enduser.id raw, since enduser=raw is the default); lowering stderr’s verbosity narrows stderr only. Under RESTACT_LOG=debug, a DEBUG-level event on an admitted target reaches stderr but does NOT export (restact.sse’s subscribe marker is exactly this case, which is why it never exports); raising stderr’s verbosity widens stderr only. The only ways to stop export of an admitted target are OTEL_SDK_DISABLED=true, RESTACT_WORKER, or removing the endpoint, never RESTACT_LOG.

The sampling decision is always local. OTEL_TRACES_SAMPLER accepts exactly always_on, always_off, traceidratio, or unset (equivalent to always_on, ratio 1.0) — any other value (parentbased_*, jaeger_remote, xray, or an unrecognized string) is a fatal: boot refusal naming the variable, but only when an exporter would be built; with no endpoint, OTEL_SDK_DISABLED=true, or inside a RESTACT_WORKER child, a bad value is never refused (the same shape as the headers refusal above). OTEL_TRACES_SAMPLER_ARG (used only by traceidratio) must parse as a finite number in [0, 1], or unset (default 1.0) — anything else (out of range, NaN/inf, or unparseable) is a fatal: boot refusal naming that variable, under the same exporting-only condition. The ratio is never applied to an INBOUND trace id, by construction — an unauthenticated caller therefore holds no amplification primitive over a host running at a low ratio.

The metrics signal exports on the same OTEL_EXPORTER_OTLP_METRICS_ENDPOINT/base-URL wiring as the other two signals. The instruments: two semconv HTTP-layer ones (http.server.request.duration, http.server.active_requests); the invoke path (restact.invoke.duration, restact.invoke.fuel, restact.invoke.inflight); process-isolation spawn (restact.worker.spawn.duration); the store (restact.store.op.duration); events (restact.events.subscribers, .published, .dropped); schedules (restact.schedule.fired, counting a schedule tick only — never a subscription delivery); verb lifecycle (restact.verb.lifecycle); egress and LLM calls (restact.egress.calls/.duration/.bytes, restact.llm.calls/.tokens — never a connector id or a model name, both unbounded caller-chosen values); auth (restact.auth.decisions, never counting an anonymous request); policy (restact.policy.decisions, counted once at every authorizing decision, data-plane included); and the guest-log limiter (restact.guest.log.dropped, reason only, never a route). Three instruments — the two invoke ones plus restact.verb.lifecycle — carry a verb route label bounded by an explicit cardinality limit of 500 attribute sets (not 500 routes: a set is the route combined with every other label on that instrument, so a legitimate host can fold well under 500 distinct routes in ordinary traffic). Past the limit the SDK folds every further set into one synthetic point carrying otel.metric.overflow=true and no route — permanent until restart, which is why the access log (below) stays the record of last resort once that happens. Span-derived rates (the collector’s spanmetrics connector, with an explicit dimensions allowlist) are sampling-dependent below ratio 1.0: they undercount by the sampling ratio, so use the metrics above for rates. No metric anywhere carries enduser.id or a concrete object path.

The server prints one boot line naming every signal that actually exports, e.g. telemetry: otlp http://otel-collector:4318 traces,metrics,logs sampler=1.0 enduser=raw export=ok for a base-URL endpoint (which drives every signal it enables at once), or, with only OTEL_EXPORTER_OTLP_LOGS_ENDPOINT set, telemetry: otlp http://collector:4318 logs … — a logs-only host never prints none. export= is always ok: the boot-time flush runs before anything has been queued, so it sends nothing and says nothing about whether the collector is reachable (the boot line does not check reachability). The host boots and serves either way.

Security

Section titled “Security”

Caution

The default configuration is open: no access control.

With no RESTACT_JWT_SECRET set, the host runs anonymous-only: every request is the anonymous principal, every anonymously-uploaded verb is owned by anonymous, and any caller is therefore its owner. That means anyone can upload, replace the code of, re-policy, or delete any verb via the management plane (PUT/DELETE on :verb/code|policy|props).

This is intentional for local development; the default bind is 127.0.0.1. Do not expose a host beyond localhost without setting RESTACT_JWT_SECRET.

The threat model is untrusted, possibly malicious uploads from day one. The defenses, layered:

  • Sandbox. WASI 0.2 components with no ambient authority; a verb reaches only what its WIT world imports. No world offers wasi:sockets, and wasi:filesystem is linked with no directories. Disallowed imports are rejected at upload (403).
  • The built-in site is opt-in. RESTACT_BUILTIN_SITE (unset by default, see above) also gates the repo_doc fallback, which serves docs/, openapi/, examples/, conformance/ and wit/ from the process’s own working directory. That is a working-directory disclosure surface, so it stays off unless the site is explicitly enabled. It never serves spec/: /spec/… answers 404. A symlink that resolves outside the directory it was requested under answers 404 too, as does any of those directories when it resolves outside the working directory or to the working directory itself.
  • Resource limits. Epoch (wall-clock → 408), fuel (CPU → 429), memory (507) on every invocation, on both executor backends.
  • Host and origin checks. Every request’s Host must be a loopback name or listed in RESTACT_ALLOWED_HOSTS, which stops DNS-rebinding pages from reaching a local host; a non-loopback bind without that list refuses to start. A browser POST/PUT/PATCH/DELETE, and any /mcp request, from another origin is refused unless RESTACT_CORS_ALLOW_ORIGIN admits it, which stops cross-site request forgery through a cookie-session proxy or against an open host.
  • Authorization. HS256 bearer auth + the owner/public policy, runs-as-caller — a verb can never exceed the caller’s authority.
  • Anonymous mutation. Once ANY auth is configured (RESTACT_JWT_SECRET, the RESTACT_OIDC_* set or RESTACT_TRUSTED_IDENTITY_HEADER), an anonymous caller may not mutate: deploy, :verb management writes and data-plane PUT/PATCH/DELETE answer 401. Reads and execute-policy-gated action invocation stay open. With no auth configured the deployment is intentionally open.
  • Quotas. Per-tenant fuel/call caps, fail-closed — lifetime cumulative, or a per-window budget with RESTACT_QUOTA_WINDOW_SECS. RESTACT_QUOTA_OBJECTS caps the objects each owner holds; with no auth configured all callers share one anonymous count.
  • Composition safety. Declared call graph, single shared budget, depth/fan-out/cycle bounds, attenuation.
  • Process isolation. RESTACT_ISOLATION=process runs each request in a worker subprocess for cross-tenant memory isolation.
  • Admin surface is deny-by-default. The operator clean-reset (POST /admin/reset) does not exist until RESTACT_ADMIN_RESET names who may trigger it; configuring public on an exposed host hands every visitor a wipe-the-world button — gate it on a role/subject in any multi-tenant deployment.
  • Log hygiene. Every caller-, guest- and deployer-chosen value the host writes into a log line is escaped first, so a route, object path, principal label or a guest’s own error text cannot forge a second line on stderr. Operator-configured URLs have credentials removed before they appear in a log line or error. See Log hygiene below.
  • OpenBao settings. RESTACT_SECRETS_URL (feature openbao) must be the final address. Redirects are not followed, because every request carries the backend token in the X-Vault-Token header and a followed redirect would resend it to a host the configuration never named. Each call refuses any status outside its allowlist as a secrets-backend error: resolve, meta and ping accept 200 only, delete and put accept 200 or 204. A 404 means “not found” for resolve and meta and “already purged” for delete. This is the same posture as RESTACT_OIDC_JWKS_URL. A plaintext http:// RESTACT_SECRETS_URL to a non-loopback host boots with one warning: line naming the variable, the scheme and the host (never the query string or mount path). Userinfo (user:password@) in the URL is refused at boot, because the credential always comes from RESTACT_SECRETS_TOKEN_FILE. A query string or fragment is refused at boot too; both checks run on the raw string before it is parsed, so a value that does not parse cannot skip them. Every remaining error, warning and boot line that mentions the URL redacts a query string or fragment as well.

Caution

Object data plane. The data plane is first-writer-owns: the first writer of an object owns it ($owner) and only the owner may write its undeclared properties. But under the anonymous-open default every caller is anonymous, so they all share ownership — treat an exposed, unauthenticated host’s undeclared object data as world-writable, and enable auth. Declared properties follow their acl/final; the reserved @/$ namespaces are unaddressable; shared properties aren’t writable via the data plane; per-object size + RESTACT_QUOTA_CALLS bound growth. Verbs that emit text/html (e.g. render-html) render attacker-controlled data: the host sends nosniff + a strict CSP, but don’t serve such output same-origin with privileged cookies.

Log hygiene

Section titled “Log hygiene”

Escaping applies to every value a caller, a guest or a deployer can choose and the host writes into a log line: routes, object paths, principal labels and a guest’s own thrown error text. The escapers cover ASCII control and newline bytes, the C1 control range (U+0080 to U+009F) and the Unicode line breaks U+0085, U+2028 and U+2029, so one event is always one line. Unicode format characters (category Cf: bidi controls, zero-width characters, the soft hyphen) are escaped too, because they reorder or hide text in a log viewer. Ordinary non-ASCII, combining marks and single-code-point emoji pass through unchanged; a ZWJ emoji sequence is split at each joiner, and a tag-sequence flag and a ZWNJ are escaped, since all three are Cf. When an error embeds more than one caller-controlled value (a governed-tree denial that names both the caller’s path and an ancestor), the whole rendered text is escaped as one unit. Secret and stored content is never quoted back.

Operator-configured URLs (RESTACT_OIDC_JWKS_URL, RESTACT_SECRETS_URL) have user:password@ or user@ userinfo stripped before they appear in a boot line, an error or an OpenBao status message. A value with no @ prints unchanged. A value that fails to parse, or whose @ does not introduce real userinfo, prints as the fixed literal <unparseable url>, never any byte of the input. Otherwise the userinfo is cut from the operator’s own spelling and the result is checked against the parsed URL, falling back to the same placeholder on any mismatch.

Two limits follow from this. An ordinary @ outside the authority (https://host/a@b, ?tenant=a@b) looks like misplaced userinfo and also prints as <unparseable url>. And a credential placed in the query string of RESTACT_OIDC_JWKS_URL prints unchanged, so keep credentials out of it. RESTACT_SECRETS_URL is stricter: a query string or fragment is refused at boot and redacted wherever the URL is printed.

Other diagnostics follow the same rule. A JWK’s key material is never logged, only its kind (oct, OKP or unrecognized). A corrupted on-disk object is reported by line and column, never by quoting the record. A PostgreSQL row with the wrong shape reports one fixed message naming the row’s kind, for example invalid deployments/object/registration record (schema mismatch).

A present but unparseable filesystem deployments.json or registrations.json is never read as empty, because the next write would serialize an empty map over the file and destroy every earlier record. FsStore::open refuses to load such a file and reports its path, the parse error category and the line and column, with the remediation (restore from backup, or move the file aside to start with no deployments or registrations). Each later deployment or registration write re-reads the manifest first and refuses, leaving the file untouched, if it no longer parses. A missing file still means no records. At boot, any failure to open RESTACT_DATA_DIR (an unwritable directory, a corrupt format.json, a corrupt manifest, or a page-token.key that is not a 32-byte regular file owned by the server’s user and readable and writable by the owner only) is a fatal refusal: one fatal: line on stderr and exit 1, never a fallback to an ephemeral store. The page-token key file is hard-linked into place, so a data directory on a filesystem without hard links also refuses boot. A refused write on a running host answers 500 store-error.

Who may define a verb where

Section titled “Who may define a verb where”

Two different questions, with two different answers — conflating them is how a multi-tenant deployment ends up with a hole:

  • Replacing an existing verb is governed by that verb’s own write ACL, on every interface — POST /v1/modules at an already-registered exact route is the same operation PUT :verb/code performs, and both are gated. An authorized non-owner gets a code grant only: the owner and policy are preserved verbatim, exec= is refused (400), runs_as=owner is refused (403), and a runs-as-owner verb is replaceable by its owner alone. PUT :verb/policy and DELETE :verb/code are owner-only (manage).
  • Defining a verb at a route nothing is registered at yet is first-deployer-owns — there is no prior registration whose ACL could be consulted. On a multi-tenant host the authority that answers “may this principal define a verb here?” is object ownership, and it is consulted only in the coupled binding modes:

Wildcard routes are covered too. A route with {id} segments is gated on its deepest concrete ancestor — the literal prefix up to the first wildcard — so ws/{id}:pageView and ws/{id}/pages/{id}/blocks/{id}:cellView both require ownership of ws. A route with a leading wildcard ({id}:v) owns no object at all and is refused (409) in the coupled modes; a truly unbound service-root verb (:bulkPing) binds to root, so the ownership gate does not apply to it. Root scope has its own rule, below.

Every verb deployed at root scope is operator-only. Root scope is the unbound service root (:bulkPing, :get) or a leading-wildcard route ({id}:get). A verb bound there is reachable from every object on the host. A reserved representation accessor (get, list, create, update, set, delete) bound there answers every bare data-plane request that has no more specific accessor, and runs with the caller’s authority, so any principal able to plant one could read, or rewrite as another user, every object on the host. Whenever auth is configured, in every binding mode (implicit included), POST /v1/modules, PUT :verb/code and POST :verb/rollback on a root-scope route answer 403 unless the caller matches RESTACT_ADMIN_RESET (the operator; a path-scoped sub-token never qualifies). The rule covers any verb name, the lifecycle hooks (onCreate, onChange, onDelete) included: a root hook sees every creation’s path and creator. With no operator configured nobody may deploy one. A verb bound to an object the caller owns is unaffected, as is an anonymous-open host (no auth).

Three companion rules close the same hole. (1) Root scope is the registry’s own parse: an object path must be canonical on POST /v1/modules and on every :verb/<prop> route, so a path with an empty segment or a leading or trailing / (/:get, //:get, /{id}:get, %2F:get, a//b:zap) is 400 invalid-input for every caller, the operator included; those spellings would otherwise alias root scope and dodge the gate under implicit binding. (2) PUT :verb/props at root scope is operator-only (403 for everyone else on an auth-on host): a declared property’s ACL is resolved registry-wide, so a declaration on a root-scope verb would reshape every object’s reads and writes: a property ACL only narrows an object’s own policy, but it can still hide a member, wedge it final or inject a default everywhere. (3) The operator may remove any root-scope verb: on an auth-on host DELETE /v1/:get/code (and likewise any other root-scope route) by a caller matching RESTACT_ADMIN_RESET succeeds even when the operator does not own the verb; everyone else is unchanged. This is the clean-up for a registration planted earlier; /admin/reset wipes the whole host and is not the remedy. A delegated request is never the operator, even when its grant’s subject matches RESTACT_ADMIN_RESET: it is an ordinary caller at the four operator paths (deploy via POST /v1/modules, PUT :verb/code and rollback, root PUT :verb/props, and the operator root DELETE). To find a planted root-scope verb, read the verbs listed in discovery (GET …/meta answers 403 to the operator on a verb it does not own, so it cannot be used for this). Deployments are stored under their canonical route (an empty segment is dropped and every {name} is spelled {id}). A server that finds a record stored under a non-canonical spelling, with or without a row already under the canonical spelling, refuses to boot, names the route and leaves the store untouched. To switch a planted registration off while you remove it, RESTACT_ACCESSOR_DISPATCH=off disables accessor dispatch entirely and RESTACT_LIFECYCLE_HOOKS=off disables lifecycle hooks (RESTACT_ACCESSOR_DISPATCH=off does not stop hooks).

Seed your collection roots (ws for ws/{id}:…) with an operator credential before users can reach the port. The first writer owns a root that does not exist yet, and the owner of a root may define verbs that resolve on every entity beneath it.

Three consequences to plan for before switching a live deployment to a coupled mode:

  1. strict refuses a deploy onto an object that does not exist yet — create the object first.
  2. The gate reads $owner, not the object’s $policy: granting someone write on an object (directly or through a governed anchor) does not let them define verbs on it.
  3. Creating an object under an existing collection root accepts that root owner’s verbs, accessors and hooks for it. A create that would sit above objects or verb definitions owned by someone else is refused 409 (ancestor-claim) unless one of the RESTACT_ADMIN_REOWN subjects makes it directly with X-Restact-Operator-Exempt: ancestor-claim.

An object’s owner may deploy a more specific verb that takes precedence over an inherited one on that object. Verbs run as the caller, so a visitor who invokes a verb on someone else’s object runs code that object’s owner chose, with the visitor’s authority. Deploying the inherited verb with ?runs_as=owner does not change this, because the owner’s verb is a separate definition. Treat verb output as untrusted at the client. A visitor who only needs to read can use a short-lived read-only path-scoped token where the host offers one: it reads the stored representation and never runs a verb or an accessor.

Production checklist

Section titled “Production checklist”

Before exposing a host beyond localhost:

  • RESTACT_JWT_SECRET set (auth on, so the host is no longer anonymous-only).
  • If using RESTACT_TRUSTED_IDENTITY_HEADER: restact is reachable only through the trusted proxy, and that proxy sets the header and strips any client-supplied copy (otherwise identity is spoofable). Prefer RESTACT_OIDC_* for a cryptographically-verified forwarded token where you can — it needs no such reachability assumption.
  • If using RESTACT_OIDC_*: all three of RESTACT_OIDC_ISSUER / _JWKS_URL / _AUDIENCE are set (audience validation is mandatory), the JWKS URL is HTTPS, and RESTACT_OIDC_AUDIENCE matches the audience your IdP mints for restact. Egress to the issuer’s JWKS host on 443 is allowed (a blocked fetch fails closed → all OIDC tokens 401).
  • Object data ACLs declared on any object whose data isn’t meant to be world-readable/writable (undeclared = public). RESTACT_QUOTA_CALLS set to bound data-plane writes.
  • RESTACT_OBJECT_BINDING left at its authenticated-host default strict (or auto-create) on any host where more than one principal deploys verbs — do not override it with implicit, which lets any authenticated caller define a verb at any not-yet-registered route, including under another principal’s object paths (Who may define a verb where). With it set: every collection root a wildcard-rooted verb binds to (ws for ws/{id}:…) is created, credentialed, before the host is reachable by users — roots are first-writer-owns.
  • RESTACT_DATA_DIR or RESTACT_DATABASE_URL set (a durable store; process isolation needs one of them).
  • RESTACT_ISOLATION=process for cross-tenant memory isolation.
  • RESTACT_QUOTA_FUEL / RESTACT_QUOTA_CALLS set (denial-of-wallet defense), plus RESTACT_QUOTA_WINDOW_SECS on any long-running host — without it the caps are lifetime cumulative and every active tenant eventually trips permanently.
  • RESTACT_QUOTA_OBJECTS set (for example 10000) when the deployment accepts writes from untrusted principals. It needs authentication to be per-user; without it all callers share one count.
  • RESTACT_REQUEST_TIMEOUT_MS / RESTACT_MAX_INFLIGHT / RESTACT_WORKER_TIMEOUT_MS reviewed for your load.
  • RESTACT_BIND set deliberately, behind TLS termination.
  • RESTACT_ALLOWED_HOSTS lists exactly the names clients use (the public name behind a proxy, plus any in-cluster service name). Avoid * unless the proxy in front pins Host.
  • The management plane is reachable only by trusted principals (policy review).
  • If running active-active (RESTACT_DATABASE_URL): the DB link is encrypted (sslmode=verify-full with a CA, not RESTACT_PG_ALLOW_PLAINTEXT); /readyz is wired as the orchestrator readiness probe (it does a SELECT 1, so a node whose DB link is down is drained) and the static /healthz as liveness; Postgres max_connections ≥ N × (RESTACT_PG_POOL_SIZE + RESTACT_PG_LOCK_POOL_SIZE + a few LISTEN conns), plus up to RESTACT_MAX_WASM_INFLIGHT worker conns under process isolation; a large cluster is fronted by PgBouncer in session mode (transaction mode breaks the session advisory locks).

Container

Section titled “Container”

The Dockerfile image already sets RESTACT_BIND=0.0.0.0:8080, RESTACT_DATA_DIR=/data and RESTACT_ALLOWED_HOSTS=localhost, so it answers at http://localhost:8080 and refuses any other Host until you set the names clients use. Pass any other variable with -e and persist /data with a volume. Pull a released image or build one from a checkout (make docker-build IMAGE=restactd; see Development → Docker).

A bind-mounted data dir (-v ./data:/data), or a named volume that already holds files owned by another uid, must be writable by the image’s non-root user (uid 65532), or the container refuses to boot (an unwritable RESTACT_DATA_DIR is a fatal error, never a silent fallback to in-memory). A fresh, empty named volume (-v restact-data:/data, as above) gets the right ownership automatically. Fix the others as in Run with Docker.
