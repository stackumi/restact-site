Use restactd from AI agents

An AI agent can call the verbs on a restactd server as MCP tools, deploy new verbs when it needs one that does not exist, and follow skills that teach it the HTTP API. This guide connects an agent three ways: the MCP endpoint built into the server, the restact mcp bridge, and the agent plugins.

Prerequisites

Section titled “Prerequisites”
  • A running restactd (Quickstart).
  • An MCP client such as Claude Code, or curl to follow the protocol by hand.
  • For authentication, a token as described in Add authentication.

Choose a connection

Section titled “Choose a connection”
OptionWhat the agent getsRuns as
Built-in MCP endpoint (RESTACT_MCP=1)Four fixed tools: list and invoke verbs, list and read objects. No writes, no deploy.Part of the restactd process
restact mcp bridgeOne tool per verb on the server, plus tools to deploy, inspect and manage verbs and to read and write object data.A separate process that is an ordinary HTTP client of the server
Agent pluginsSkills that teach the agent the HTTP API, and the restact mcp bridge registered for you in Claude Code.A skill set plus the bridge

In every case the agent acts with the caller’s token, so it can do exactly what that user can do and nothing more.

The endpoint speaks MCP over HTTP at /mcp. It is stateless, so GET /mcp answers 405, and discovery lists the mcp-facet feature. Initialize a session and list the tools:

The server offers four tools:

ToolWhat it does
list_verbsReturns every deployed verb’s route, kind and descriptor, the same inventory as GET /.well-known/restact.
invoke_verbInvokes a verb by its concrete route, for example me:whoami. A function runs as GET and an action as POST. Takes an optional input object.
list_objectsLists readable objects, like GET /v1. Takes a prefix; end it with /. A page can come back short or empty while it still carries a nextPageToken, so keep paging until there is none.
get_objectReads one object by path.

Call a verb the way an agent would:

Each call goes through the same authentication, policy and quota path as the equivalent HTTP request. A missing or bad token comes back as a tool result with isError: true and the usual problem body, for example 401 invalid bearer token. An anonymous request follows whatever the HTTP side allows, so on a host with no authentication configured the endpoint is open too.

For a client that supports remote MCP servers over HTTP, point it at http://localhost:8080/mcp and give it the bearer token in its header configuration.

2. Use the restact mcp bridge

Section titled “2. Use the restact mcp bridge”

restact mcp is a subcommand of the restact client that translates between MCP and a restactd server. It works against any REST:ACT server, because it builds its tools from the discovery document. It gives the agent more than the built-in endpoint:

MCP surfaceComes from
One tool per verb/.well-known/restact, with input and output schemas taken from the server’s /openapi.json when it publishes one
invoke_verbAny verb by route, including ones deployed after the agent connected
deploy_verb, delete_verbPOST /v1/modules and PUT/DELETE …/code. The agent can write a JavaScript or Python verb and use it straight away.
get_verb, verb_history, rollback_verbVerb metadata, source and history
list_objects, get_object, put_object, delete_objectThe object data plane
ResourcesObjects as MCP resources

The bridge sends tools/list_changed after each deploy, so a verb the agent just wrote appears in its tool list. This is the forge loop: the agent finds that no tool answers a question, writes a small function verb, deploys it and calls it once instead of making many calls and carrying the intermediate results.

The common settings:

VariableEffect
RESTACT_MCP_HOST_URLThe server to bridge. Without any chosen server (this variable, RESTACT_MCP_HOSTS, RESTACT_URL, --url or a context) the bridge uses http://127.0.0.1:8080 and sends it no token.
RESTACT_MCP_HOSTSSeveral named servers, alpha=http://a:8080,beta=http://b:8080. Tool names then carry the server name as a prefix.
RESTACT_MCP_BEARERThe token presented to the server. Without it the agent is anonymous. It is not sent to the unchosen default http://127.0.0.1:8080, so set a server too (for example RESTACT_MCP_HOST_URL). RESTACT_MCP_LISTEN refuses to start with no chosen server.
RESTACT_MCP_ALLOW_PLAINTEXTThe bridge refuses to start when it would send a token to a non-loopback http:// server. 1 accepts plain http. Whatever the token, a server URL must be http or https with a host and no credentials, query or fragment, or the bridge exits 2.
RESTACT_MCP_ALLOW_DEPLOYSet a false value (0, false, off or no) to hide the deploy and delete tools and give the agent a read and invoke bridge only.
RESTACT_MCP_ALLOW_DATA_WRITESSet a false value to hide put_object and delete_object.
RESTACT_MCP_ALLOW_VERB_ADMIN, RESTACT_MCP_ALLOW_REGISTRATIONSOff by default. A true value (1, true, on or yes) adds tools to set verb policy and to create schedules and subscriptions.
RESTACT_MCP_LISTENServe MCP over HTTP at http://<host:port>/mcp instead of stdio.

Over the HTTP transport, an Authorization: Bearer header on each MCP request replaces the configured token for that request. Several people can then share one bridge and each act as themselves. A non-loopback RESTACT_MCP_LISTEN address makes the configured token the identity of anyone who can reach the port, so the bridge refuses to start there unless you also set RESTACT_MCP_ALLOW_NONLOOPBACK to 1 or true. Any other value exits 2.

The bridge has no authority of its own. Whatever the agent deploys runs in the server’s sandbox with its capability confinement, metering and quotas.

3. Install the agent plugins

Section titled “3. Install the agent plugins”

The repository ships two sets of Agent Skills. A skill is a SKILL.md that tells an agent how to do a task, here checked against the server’s discovery document so it works with any compliant server.

PluginFor an agent that is
restact-clientUsing a live server. Skills cover HTTP basics, auth tokens, publishing verbs, the data plane, and schedules and events. It also registers the restact mcp bridge as an MCP server in Claude Code.
restact-builderBuilding a system on restactd. Skills cover embedding the host, building applications from verbs, the Rust SDK, conformance, and deployment.

--check reports which installed skills are out of date, and --uninstall removes them.

On Claude Code, restact-client starts the bridge through a script that locates a restact binary, so it picks up the same RESTACT_MCP_HOST_URL and RESTACT_MCP_BEARER variables from the environment Claude Code is launched in. The first start can take around 30 seconds if the bridge has to be built. If the connection times out, raise MCP_TIMEOUT and reconnect. The binary is cached for later sessions.
