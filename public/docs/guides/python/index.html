Write verbs in Python

Upload a Python file and call it over HTTP. The host does not compile it: it stores the source and runs it with monty, a Python interpreter written in Rust, inside the same sandbox and limits as every other verb.

monty runs a subset of Python. This guide shows the working path first, then lists exactly what the subset includes and leaves out. For the cross-language reference, see the authoring reference.

Prerequisites

Section titled “Prerequisites”
  • A running restactd with the Python tier enabled. Install shows how to build the runner; a host without it answers 415 to a Python upload.
  • curl. Commands use localhost:8080, and -g keeps curl from treating {id} as a glob.

Check that the host accepts Python:

A function you can call with GET

Section titled “A function you can call with GET”

  1. Write the verb. It defines invoke(input), where input is the request body or ?input= value as a string.

  2. Deploy it as a function. lang=text/x-python names the language.

    The 201 body lists the imports the verb ended up with and its content hash.

  3. Call it.

What just happened: the return value is turned into a response body. A str passes through unchanged, bytes pass through as bytes, None is an empty body, and a dict, list, number or bool is serialized as JSON. A tuple serializes as {"$tuple":[...]}, so return a list when a client will read it.

Replace a verb’s source with PUT /v1/py:hello/code and the same Content-Type; the response is 204. GET on the same path with Accept: text/x-python returns the stored source.

A script that does not parse is refused at upload. Unsupported syntax is caught there too, with the interpreter’s own message:

What the Python subset supports

Section titled “What the Python subset supports”

Input and output are text. The interpreter version string is 3.14.0 (Monty).

These work:

  • def, lambda, closures, recursion (capped at 1000 frames), default arguments, *args and unpacking such as a, *b = [1, 2, 3].
  • if, for, while, try/except/raise, assert.
  • List, dict and set comprehensions, slicing (s[::-1]), f-strings including format specs (f"{x:.2f}").
  • class definitions, % string formatting and str.format.
  • eval() and exec(), described below.
  • str, int (arbitrary size), float, bool, list, dict, set, tuple, bytes, and builtins such as len, sorted, sum, range, isinstance and type.
  • async def helpers driven from a plain invoke with asyncio.run(...), such as return asyncio.run(double(21)).
  • match statements and dataclass field.
  • import json, re, math, sys, typing, asyncio, collections, itertools, functools, datetime (values, not the clock), random (after random.seed(n)), hashlib (digests; not file_digest or scrypt), csv, bisect, tomllib, decimal and the string functions of os.path.

These do not work, and fail at upload (422), fail when the line runs, or return an unusable value:

  • Generators (yield) and other unsupported statements (del, class inheritance, async for/async with): refused at upload.
  • The clock and sleep (time.time(), time.sleep(), datetime.datetime.now(), datetime.date.today()), random without an explicit random.seed(...), open(), directory listing (os.listdir, os.scandir, os.walk, Path.glob, Path.rglob, Path.iterdir), os.path existence and stat checks, path resolution (os.path.realpath), and environment reads fail with unsupported operation (os/filesystem). A verb has no clock or entropy of its own.
  • socket, subprocess and other modules not listed above raise ModuleNotFoundError, which a script can catch with except ImportError.
  • async def invoke: the host calls invoke directly, so it must be a plain def. A coroutine comes back as {"$repr":"<coroutine object invoke>"} instead of a result.

print() does not reach the response; use log().

eval(source) and exec(source, namespace) run inside the same sandbox, with the script’s own names and the same limits, and add no reach the script does not already have. Never pass caller input to them. The code would run with the verb’s authority, including runs_as=owner, so a caller who controls the string controls what the verb does.

An action that uses object data

Section titled “An action that uses object data”

An entity verb is bound to an object. Inside the script, obj reads and writes that object’s data.

Property values are typed. obj.get returns None when the property is absent or the caller may not read it. A kind=function verb may read but not write; a write is refused with 403 and forbidden-side-effect.

Typed values. A property holds a string or a JSON value, and the runner maps them at the boundary:

For obj.set_at_if, expected maps the same way, and None or leaving it out means “absent”. Query rows carry the same typed .properties and .order_value.

get_bytes returns a BinaryValue named tuple, so content_type, data = obj.get_bytes() unpacks. A value over 6 MiB (a quarter of the script heap) raises RuntimeError with the code memory-limit; read it from a Rust verb. Return bytes to send them back unchanged.

obj.query returns a page with .objects and .cursor. Each row has .path, .properties (a dict of the properties the caller may read) and .order_value. predicate is a dict {"key": ..., "value": ...}. .cursor is None once the result is exhausted; otherwise pass it straight back as cursor= to read the next page:

The host clamps limit to a per-call maximum. See Store and query object data for ordering, predicates and the cursor.

Ask a model

Section titled “Ask a model”

llm.complete(request) makes one text completion through a connector. The verb needs the llm grant and cannot be a function. The request is one dict:

connector and messages (a non-empty list of role/content dicts, where role is "user" or "assistant" and the host refuses any other) are required; system, model, max_output_tokens and temperature are optional, and None counts as left out. The result has .text, .stop_reason, .model and .usage (input_tokens, output_tokens, cache_read_tokens, estimated_usd_micros, meter_tier). A bad field raises RuntimeError with the code invalid-input and the field named. Treat .text as untrusted input.

Read the caller

Section titled “Read the caller”

caller.actor() is the delegated client’s id when the request runs under a delegated token, else None. caller.invoker() is the principal on whose behalf the whole call tree runs; it is None unless the verb was deployed with ?invoker=1.

On a host with no authentication, a call returns {"subject":null,"anonymous":true,"roles":[],"scopes":[],"groups":[],"dept":null,"actor":null,"invoker":null}. With a bearer token, the subject and claims come from the token. Add authentication shows how to set that up, and Identity and authority explains why the verb always runs as the caller.

Handle errors

Section titled “Handle errors”

An uncaught exception becomes a 422 with restact_code: script-error, and the traceback goes into detail. Callers see that text, so keep secrets out of messages.

A failure in a host capability, such as a denied write or an undeclared compose, raises RuntimeError. The structured code is inside the message, between \u0001 characters:

Rethrow what you do not handle: an uncaught host error reaches the caller with its original status (403 for forbidden), while a replacement exception becomes a generic script-error.

Limits

Section titled “Limits”

Each invocation runs under per-request limits that discovery reports under defaultCapabilities: 200 million compute units, 2 seconds and 32 MiB by default. The runner caps its own heap at 24 MiB.

  • A loop that never ends, or a very large comprehension, stops with 429 and restact_code: cpu-budget.
  • Unbounded recursion stops with a Python RecursionError traceback in a script-error.
  • Source is parsed on every invocation, out of the run fuel, so keep hot scripts small and give a large source a higher ?fuel= (see Capabilities and budgets).

Editor completion and type checks

Section titled “Editor completion and type checks”

obj, caller, llm, log and compose are installed by the runner, so an editor reports them as undefined. sdk/python/restact.pyi and sdk/python/__builtins__.pyi declare them for Pyright and Pylance; mypy needs a TYPE_CHECKING import. sdk/README.md has the setup. The stubs list only what the Python runner provides.
