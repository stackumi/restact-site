Schedules and subscriptions

A schedule runs an action verb at a fixed interval. A subscription runs an action verb whenever an object publishes an event. Both are registered over HTTP as resources, so you create, list and delete them with the same requests you use for everything else.

Prerequisites

Section titled “Prerequisites”
  • A running restactd with the JavaScript tier (see Install). The examples use http://localhost:8080 with no authentication configured.
  • curl.

What just happened

Section titled “What just happened”

The host keeps a timer for each schedule and runs its target through the normal invoke path, including limits and quotas. A subscription is delivered from the same stream that feeds server-sent events: every data-plane write publishes an event on the object’s path, and the host runs each subscription registered for that topic.

Both kinds of firing run as the person who registered them. They carry that person’s subject and nothing else, so a target must be executable by the registrant’s subject alone. Registering a target the registrant cannot execute is refused with 403, because the registration would never fire.

Restarts

Section titled “Restarts”

Registrations are stored with your data, so they survive a restart. A restarted host resumes each schedule from its recorded lastFiredAt. If one or more intervals were missed while the host was down, it fires once to catch up and then returns to the normal rhythm; it does not replay every missed interval.

To check it, register the 10-second schedule above, stop the host for about 35 seconds, and start it again over the same data directory. The counter goes up by one after the restart, not by three.

Who can see a registration

Section titled “Who can see a registration”

Once you configure authentication (Add authentication), an anonymous caller cannot register or delete anything (401). Schedules and subscriptions are owned by the caller who made them:

Bob’s listing leaves out Alice’s schedules. A GET or DELETE by id on one of them answers 404 for Bob.

Limits and the kill switches

Section titled “Limits and the kill switches”
VariableDefaultEffect
RESTACT_SCHEDULE_MIN_INTERVAL_SECS10Smallest accepted intervalSeconds.
RESTACT_MAX_SCHEDULES32Live schedules per tenant.
RESTACT_MAX_SUBSCRIPTIONS32Live subscriptions per tenant.
RESTACT_SUB_MIN_GAP_MS1000Minimum gap between two firings of one subscription. This bounds a loop where a subscribed action writes the object it subscribes to.
RESTACT_DISABLE_SCHEDULESoff1 turns the schedule timer off. Registration answers 501 and discovery omits the schedules feature.
RESTACT_DISABLE_EVENTSoff1/true/on/yes turns eventing off. Subscription registration answers 501, existing subscriptions stop firing, and discovery omits verb-subscriptions. It also stops the events the host publishes on each data-plane write and the server-sent event stream. Lifecycle hooks still fire.

RESTACT_DISABLE_SCHEDULES does not affect subscriptions, and RESTACT_DISABLE_EVENTS does not affect schedules. The full list is in Configuration.
