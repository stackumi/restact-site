Store and query object data

Every path under /v1 can hold data: a flat set of string properties. You read and write it with plain HTTP, list it with a paginated collection endpoint, and let verbs act on it through the object capability.

This guide covers the HTTP side first, then the verb side: reads and writes, queries, the object’s own path, and atomic invocations.

Prerequisites

Section titled “Prerequisites”
  • A running restactd on localhost:8080. Object data needs the data-plane feature, which the reference host advertises.
  • The JavaScript tier for the verb examples. Rust and Python equivalents are noted where they exist.

Write, read and delete an object

Section titled “Write, read and delete an object”

  1. Store properties with PUT. The body is a JSON object whose members are any JSON value (stored typed), or null to remove a property, and the write merges into whatever is already there.

    The response is 204. Creating the object needs no earlier step.

  2. Read it.

  3. Add a property. Because PUT merges, a second write that names only extra keeps title and kind.

  4. Remove a property. A null member removes that property and leaves the others alone.

    A null for a property that is not set changes nothing. Removing needs the same authority as setting: the object’s write policy and the property’s write ACL decide, and a final property that is set answers 409 with code property-final. A null for $policy removes the object’s own policy, so the object falls back to its governing anchor’s policy or the default. It needs the authority to rewrite the policy, and it is refused on a secrets-mount slot (422), under the connector prefix (422) and, with governed creation on, at a path no anchor governs (403). A null for $owner, any other $ attribute or an @ name is 400, and so is any other value that is not a string. A PUT with several members is one write, so a refused member refuses all of it. A property that has been removed reads as one that was never set, so an inherit property falls back to its ancestor’s value or its default. Writing an empty string is not a removal, because the property stays present. Removing the last property leaves the object in place (GET answers {}) and fires onChange; DELETE deletes it.

  5. Delete the object.

GET returns only the properties the caller may read. POST on an object path answers 405 unless a create accessor verb is deployed there, and PATCH answers 405 unless a set or update accessor is. Without accessors the data plane takes GET, PUT and DELETE; to invoke a verb, POST to a path with a :verb suffix. An object holds at most 1024 properties and 1 MiB of data; going past either is 413. HTTP API lists the rest of the rules.

Conditional requests

Section titled “Conditional requests”

Reads carry an ETag. Use it for caching and for safe updates.

The last request fails because the successful write changed the tag. DELETE honours If-Match as well. A client that loses a race gets 412, rereads and retries.

Binary values

Section titled “Binary values”

A PUT with a Content-Type that is not JSON stores the body as a binary value. A GET serves the same bytes back with the stored type.

The body is byte-identical to what you stored. The ETag is a hash of the content, so If-None-Match gives 304. Script-capable types (text/html, image/svg+xml, any +xml) are served as downloads instead of rendering inline. A value over RESTACT_MAX_BLOB_BYTES (8 MiB by default) is 413; see Configuration.

An object holds either a binary value or JSON properties; a JSON content type (application/json, application/*+json) is the property form. A compiled Rust verb can read the bytes with restact_sdk::object::get_bytes(), which suits read-time transforms such as resizing an image. A JavaScript or Python verb reads one with obj.getBytes() or obj.get_bytes(), up to 6 MiB (a quarter of the script heap); a larger value raises memory-limit, so read it from a compiled verb.

Inherited values

Section titled “Inherited values”

A property declared with inherit takes its value from the nearest ancestor object that stores it when the object itself does not. A caller receives the inherited value only if they could read that property on the ancestor directly: the ancestor’s $policy.read and the property’s read ACL there both admit them, and the declaration in effect on the child admits them too. The child’s declaration is evaluated against the ancestor that holds the value: that ancestor’s owner, and the members the caller can read there, not the child’s owner. An ancestor that refuses is skipped and the walk continues upward. If no ancestor admits the caller, the declared default applies, checked against the child’s own declaration. The inherited value is never copied into the child; it exists only in what the caller reads.

List objects and page through them

Section titled “List objects and page through them”

GET /v1 lists the objects with stored data that the caller may read, ordered by path in byte order. Seed five notes, then list the first two that are notes:

  • pageSize sets the page length.
  • pageToken takes the nextPageToken from the previous response and returns the following page. The token is opaque and sealed by the server: pass it back unchanged, on the same filter and as the same caller. A token the server did not issue for that listing answers 400 invalid-input; an empty pageToken is the first page. When a response has no nextPageToken, you have the last page.
  • filter=name=value keeps objects whose readable property name equals value.
  • read_mask=a,b adds a values map with just those properties to each entry. Without it, an entry carries only its path and a properties count.
  • prefix=lib/ keeps only objects whose path begins with lib/. It must be empty or end in /, and it never lists lib itself. A prefix that does not end in /, or that no path can start with (a leading /, a//, a segment starting with @, a NUL), answers 400 invalid-input. Encode a literal + as %2B. Pass the same prefix with every pageToken: the token is bound to it. Send prefix only when discovery lists object-listing-prefix; an older host may ignore it.

The listing covers the whole store. To work on one subtree, use obj.query from a verb, below.

Let a verb act on its object

Section titled “Let a verb act on its object”

An entity verb such as pages/{id}:view is bound to the object in its URL, so pages/home:view acts on pages/home. The object capability is how it reads and writes that data. Everything is checked against the caller’s permissions: a verb never reads or writes what its caller could not.

Reads of an absent or unreadable property return undefined (JavaScript), None (Python, Rust) and are indistinguishable from each other. A write the caller may not make throws forbidden. Only actions may write: a kind=function verb that calls a write is refused with 403 and forbidden-side-effect.

Find the object’s own path

Section titled “Find the object’s own path”

obj.path() returns the concrete path the verb was invoked on, never the route pattern it was deployed at. A verb deployed at ws/{id}/pages/{id}:render and called on ws/w1/pages/p3 reads ws/w1/pages/p3. This lets a verb address itself without the caller passing the path in:

It returns null (None in Rust) when the verb is not bound to an object, as with an unbound :verb route, and the host advertises the feature as object-self-path. Call it again inside a composed verb and it reports that verb’s own object, not the caller’s.

Query a subtree

Section titled “Query a subtree”

obj.query returns one page of objects under a path prefix, each with its readable properties. It is a single call into the host, so it replaces one getAt per column per object, and it is a pure read: a kind=function verb may use it. The host advertises it as verb-object-query.

The options, all optional:

OptionMeaning
prefixOnly objects whose path starts with this string. Default: the whole store.
orderByA property name to sort by. Default: path order.
descendingtrue to reverse the order.
predicate{key, value}: keep objects whose key property equals value.
limitPage size. The host clamps it to its per-call maximum.

A string value sorts as a string, so zero-pad numeric strings ("02", not "2") when you order by them; stored numbers order after strings, then booleans, arrays and objects. Each row has path and properties (a plain object of the readable properties). System fields such as $policy never appear in properties.

Update safely under contention

Section titled “Update safely under contention”

setAtIf(path, name, value, expected) writes only if the property still equals expected, and throws precondition-failed otherwise; pass null to mean “only if absent”. The JavaScript guide has a complete retry loop. The check and write are atomic on the target object, and the write commits at once. The host advertises it as object-cas.

Remove a property

Section titled “Remove a property”

remove and remove_at are authorized exactly as set and set_at of the same name, so a verb never removes what its caller could not. Removing a property that is not set succeeds and changes nothing. A final property that is set fails with property-final. remove on the bound object is held until the verb returns and dropped if it fails, and gives not-found when the bound object holds no data; remove_at commits at the call, as set_at does, and fails with not-found when no object is stored at the path, because a removal never creates one. Verbs cannot touch $ attributes, so a verb cannot remove a policy. A caller who may not read the object gets not-found in place of forbidden. The host advertises the verb functions as object-remove.

Make an invocation atomic

Section titled “Make an invocation atomic”

By default, a verb’s writes to its own object are held until it returns and dropped if it fails, but each setAt to another object commits at the moment it is called. A verb that fails halfway therefore leaves its earlier setAt writes in place. Start the host with RESTACT_CONSISTENCY=atomic-invocation and the whole write set of one invocation, on the bound object and on other objects through setAt and removeAt, commits together when the verb returns, and is discarded if it fails.
