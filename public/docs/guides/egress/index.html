Outbound calls and secrets

restactd can make an outbound HTTP call on a caller’s behalf and add a stored credential to it without the credential ever reaching the caller, a verb, a log line or a stored object. This guide configures that mechanism, calls a local origin through it, and walks through the checks that keep a misconfigured host from starting.

How outbound calls work

Section titled “How outbound calls work”

A verb runs in a sandbox with no network access, so it cannot open a socket. Two host-mediated paths reach the outside world:

  • Mediated egress is a function of the Rust host API, RouteContext::mediated_call. An application that embeds restactd registers its own route and calls it. restactd adds no HTTP route for egress by itself, so there is nothing for an anonymous client to probe.
  • The llm capability lets a verb request one text completion from a model provider through a connector. It uses the same allowlist, secrets and scrubbing as mediated egress. It is a typed call, not general HTTP, and a verb that imports it cannot be deployed as a function.

This guide covers the first path. The demo embedder route POST /demo/egress exists to exercise it over HTTP and is the worked example below. It is switched on with RESTACT_DEMO_NATIVE=1 and is not meant for production.

Prerequisites

Section titled “Prerequisites”
  • A restactd binary built from source (see Install).
  • curl, openssl and python3.
  • A shell variable SECRET holding the signing secret for test tokens. Authentication is required, because a connector is owned by the person who created it. Add authentication explains the token you mint here.

2. Understand what the host refuses to start with

Section titled “2. Understand what the host refuses to start with”

Egress needs three settings to agree. If they do not, restactd exits at startup with an error: line, so a half-configured host never serves traffic.

VariableMeaning
RESTACT_EGRESS_ALLOWComma-separated host[:port] destinations the host may call. A DNS name, a *.-prefixed suffix or an address literal. Unset means the feature does not exist.
RESTACT_SECRETS_URL and RESTACT_SECRETS_MOUNTThe secrets backend, and the object-path pattern where secrets are written, for example ws/{ws}/secrets/{name}. Both must be set together.
RESTACT_EGRESS_CONNECTOR_PREFIXWhere connector objects are created, for example ws/{ws}/connectors.

An allowlist with no way to supply a credential is a mistake, so the check is one-sided: setting the allowlist without the rest is fatal, while setting the secrets mount alone boots normally and advertises secrets-management but not mediated-egress.

Private and loopback addresses are blocked as destinations unless you name them and acknowledge the risk, so a connector cannot be pointed at an internal service by mistake. A real deployment allows public hostnames and never sets RESTACT_EGRESS_ALLOW_LOOPBACK.

What just happened

Section titled “What just happened”

The route called mediated_call with the connector path and a target path. The host then did the following, in order:

  1. Resolved the caller from the token and checked that the caller can read the connector.
  2. Checked the destination against RESTACT_EGRESS_ALLOW and the target path against the connector’s pathPrefixes.
  3. Read the secret from the backend at the moment of sending and substituted it into the splice template.
  4. Sent the request with bounds on request size, response size and wall time, refusing redirects.
  5. Removed any occurrence of the secret from the response before returning it, and dropped response headers such as Set-Cookie that are not on the host’s allowlist.
  6. Wrote one audit line to the log, without the value:

Refusals you will meet

Section titled “Refusals you will meet”

These answers are the host working as intended:

RequestAnswer
A different user calls the connectoregress-denied: no connector readable at that path for this principal
A target outside pathPrefixes, such as /adminegress-not-allowed
A request body containing the literal ${secret:placeholder-in-caller-data; placeholders are only honoured in the connector’s own template
The origin answers with a redirectegress-redirect-refused; redirects are never followed
A connector whose destination is not in RESTACT_EGRESS_ALLOWegress-not-allowed: the destination example.org:9999 is not in RESTACT_EGRESS_ALLOW
A connector the secret does not list in its connectors membersecret-not-bound: a secret travels only where both its owners point

Limits and quotas

Section titled “Limits and quotas”

Hard ceilings apply to every call. A connector can only lower them.

VariableDefaultEffect
RESTACT_EGRESS_MAX_INFLIGHT8Concurrent calls in the process. Beyond it a call is refused with egress-busy.
RESTACT_EGRESS_MAX_REQUEST_BYTES1 MiBRequest body ceiling.
RESTACT_EGRESS_MAX_RESPONSE_BYTES2 MiBResponse body ceiling.
RESTACT_EGRESS_MAX_WALL_MS30000Wall-clock ceiling for one call.
RESTACT_QUOTA_EGRESS_CALLS, …_BYTES, …_WALL_MSunsetPer-principal caps that refuse calls once reached. Unset means metered but not enforced.

See Configuration for the remaining header limits.
