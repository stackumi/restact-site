Write verbs in Rust

Build a verb as a WebAssembly component with the restact-sdk crate, upload the .wasm file, and call it over HTTP. Compiled verbs run without an interpreter, accept and return binary payloads, and can read binary object values.

This guide builds two verbs: a function that turns text into a URL slug, and an action that counts hits on an object. It then shows composition.

Prerequisites

Section titled “Prerequisites”
  • A checkout of the restactd repository: the SDK is not published to crates.io, so a verb depends on it by path.
  • Rust 1.88 or newer with the wasm32-wasip2 target: rustup target add wasm32-wasip2. The repository’s Install page covers the pinned toolchain.
  • A running restactd (localhost:8080 below).

A function: slugify text

Section titled “A function: slugify text”

  1. Create a library crate. The verb is a cdylib, and the SDK is the only dependency.

  2. Implement the Verb trait and export it with one macro.

    Payload is a Vec<u8>. The input and output are raw bytes, so a verb can handle any media type; this one treats them as UTF-8 text.

  3. Build with plain cargo. The wasm32-wasip2 target produces a component directly, so cargo-component is not needed.

    The component is target/wasm32-wasip2/release/slug.wasm.

  4. Deploy it. A component upload uses Content-Type: application/wasm.

    The 201 response lists the component’s imports, which are the capabilities it can reach. This one imports only rest-act:plugin/host (logging) beside the WASI base.

What just happened: the SDK exported your Verb as the rest-act:plugin component interface. The host read the component’s imports at upload and granted exactly those capabilities, nothing more. Error::not_found(...) maps to 404. Reserved codes keep their statuses (forbidden is 403, conflict is 409), and any other code you pass to Error::new(code, message) surfaces as 422.

Choose capabilities with Cargo features

Section titled “Choose capabilities with Cargo features”

The SDK’s features decide which world, and so which host capabilities, the component imports. A verb that does not enable a feature cannot reach that capability at all.

FeaturesCapabilities the verb can reach
nonelog
composelog, restact_sdk::compose
objectlog, object data (restact_sdk::object), caller identity (restact_sdk::caller)
compose, objectall of the above
eventeverything in object, plus restact_sdk::publish; implies object

Keep the verb crate a leaf in its dependency graph. Cargo unifies features across a build, so a dependency that turned on compose would widen your verb’s world.

With authentication configured, last holds the caller’s subject. The object module also has get_at, set_at, set_at_if, remove, remove_at, shape, shape_at, query and path, and get_bytes for binary values; see Store and query object data. Reads and writes are checked against the caller’s permissions, and object::set fails with forbidden where the caller could not write.

Compose another verb

Section titled “Compose another verb”

With the compose feature, restact_sdk::compose(route, input) runs another verb. The repository ships a pair you can deploy as-is: examples/word-count-sdk (a function) and examples/summarize-sdk (an action that calls it).

The calls= list is the declared call graph; the host refuses any edge that is not on it. See Compose verbs.

Other ways to produce a component

Section titled “Other ways to produce a component”
  • cargo-component: an alternative, with a generated bindings module instead of the SDK. examples/word-count and examples/summarize use it, and scripts/build-examples.sh builds all the examples.
  • Any other language whose toolchain can emit a WebAssembly component for one of the rest-act:plugin@0.1.0 worlds in wit/ can upload with Content-Type: application/wasm. The host checks the component’s imports against the world, so it accepts any component that stays inside it. The repository ships and tests the Rust path; other toolchains are not covered here.
  • No toolchain at all: JavaScript and Python verbs.
