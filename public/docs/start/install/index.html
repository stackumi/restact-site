Install

The quickest route is to download a release archive, check it against its checksum and unpack it. You can also run a published container image, or build restactd from a clone of the repository.

Download a release

Section titled “Download a release”

Releases are on GitHub. Each one carries archives for three platforms, named by Rust target triple:

PlatformTarget
Linux, x86-64x86_64-unknown-linux-gnu
Linux, arm64aarch64-unknown-linux-gnu
macOS, Apple siliconaarch64-apple-darwin

Other platforms, Intel Macs included, build from source untested. Windows is not supported.

The examples below use VERSION for the release you want, such as 0.1.0. Substitute your own, and the target for your machine.

Pick an archive

Section titled “Pick an archive”

The host comes in two flavours. restactd is the default: it keeps data in memory, or on the filesystem when RESTACT_DATA_DIR is set, and refuses to start if RESTACT_DATABASE_URL is set. restactd-full adds the PostgreSQL backend, the OpenBao secrets backend and OpenTelemetry export, so pick it for a PostgreSQL cluster or for traces and metrics. The OpenTelemetry exporter in the -full build starts when an OTLP endpoint is set (OTEL_EXPORTER_OTLP_ENDPOINT or a per-signal one); setting OTEL_SDK_DISABLED=true turns it off whatever else is set. See Observability.

ArchiveContents
restactd-vVERSION-TARGET.tar.gzThe host, without PostgreSQL.
restactd-full-vVERSION-TARGET.tar.gzThe host with PostgreSQL, OpenBao and OpenTelemetry.
restact-vVERSION-TARGET.tar.gzThe restact client and its MCP bridge.
restact-conformance-vVERSION-TARGET.tar.gzThe conformance runner, for testing another server.
restactd-runners-vVERSION.tar.gzThe JavaScript and Python runner components alone. The host archives already contain them.
checksums.txtSHA-256 of every archive above.

Unpack and run

Section titled “Unpack and run”

Data stays in memory until you set RESTACT_DATA_DIR, for example RESTACT_DATA_DIR=$PWD/data restactd.

Each per-target archive unpacks to one directory named like the archive, holding bin/, share/ where it has one, README.md, CHANGELOG.md and LICENSE. The host archives hold:

The host finds the runners by their place next to the binary: a restactd in bin/ looks in the sibling share/restactd/runners/, so the JavaScript and Python tiers work from the unpacked directory without any setting. If you copy the binary somewhere else, copy share/ with it and keep the two side by side, for example /usr/local/bin/restactd and /usr/local/share/restactd/. The runner variables are in Configuration.

A release build reports its version number as the first line on stdout, in place of the dev a source build prints. restactd --version prints that line without starting the server.

Linux requirements

Section titled “Linux requirements”

The Linux binaries need glibc 2.28 or later. That covers Debian 10, Ubuntu 20.04, RHEL 8 and anything newer; Ubuntu 18.04 and Amazon Linux 2 are too old. On an older system the loader stops with version 'GLIBC_2.xx' not found; see Troubleshooting.

For production, pin the image by digest rather than by tag. The digests are listed in each release’s notes, and you can read one from the registry:

The attestation check also works on an image: gh attestation verify oci://ghcr.io/stackumi/restactd:$VERSION --repo stackumi/restactd --deny-self-hosted-runners. Run with Docker covers volumes, host names, compose and process isolation.

Build from source

Section titled “Build from source”

Building from source is for working on restactd itself or for a platform with no archive. restactd is built and tested on x86-64 Linux.

You need rustup 1.28 or later, git, make, curl, a C toolchain and network access. The first build compiles Wasmtime and takes several minutes.

The checkout pins Rust 1.99.1 and the wasm32-wasip2 target in rust-toolchain.toml, so rustup toolchain install fetches exactly that.

The server prints its build as the first line on stdout. A build from source reports dev as its version, and the commit it was built from, read from git in every profile; commit=unknown appears only when there is no git checkout and RESTACT_BUILD_COMMIT is unset. Without starting it, cargo run -p restactd -- --version (or restactd --version for an installed binary) prints the same line.

In a second terminal, check that the server is up:

The restact command line is a separate binary from the same checkout: cargo build -p restact writes target/debug/restact. The quickstart uses it, and the reference lists its commands.

Run cargo run -p restactd from the repository root. The host looks for the runners and example verbs at paths relative to the working directory.

Optional pieces

Section titled “Optional pieces”

Without them the server still starts. It omits a language tier whose runner is missing: discovery does not list the language, and an upload in it returns 415. With RESTACT_EXAMPLES=1 it also prints a warning: line for each example verb it cannot find.

You wantRunNotes
Python verbsmake build-py-runnerPure Rust; fetches monty from crates.io, pinned to an exact version.
The Rust example verbsmake build-examplesNeeds cargo-component. Builds the demo verb behind demo:run, which the host seeds only with RESTACT_EXAMPLES=1.
Everythingmake build-allHost, example verbs and both runners.
The browser playgroundmake runSets RESTACT_EXAMPLES=1 and serves the built-in site at http://127.0.0.1:8080/playground.html.

./scripts/bootstrap.sh installs the whole toolchain in one step: the pinned Rust, the wasm32-wasip2 target, wasm-tools, cargo-component, wac and wkg, and the repository’s git hooks. It is idempotent. You need it only if you will write Rust verbs or work on the repository; the JavaScript path above needs cargo-component alone.

If you use mise, mise.toml in the repository pins the same toolchain.

make help lists every target.

Build a Docker image

Section titled “Build a Docker image”

The Dockerfile is a multi-stage build. The builder stage compiles the host, the example verbs and both runners. The runtime stage is the distroless cc-debian13 base, with no shell and no package manager, running as the non-root uid 65532. It contains the binary, the built verbs and the runners. You need Docker, git and make.

Things to know about the image:

  • It listens on 0.0.0.0:8080 inside the container, and make docker-run publishes that port on 127.0.0.1 only. PORT=0.0.0.0:8080 make docker-run publishes it on every interface, which serves an unauthenticated server to your network unless you configure authentication.
  • It persists to the /data volume. make docker-run mounts the named volume restact-data there, so data survives restarts.
  • It answers only to the Host names localhost, 127.0.0.1 and [::1] until you set RESTACT_ALLOWED_HOSTS to the names your clients use.
  • It has a health check that calls /healthz every 30 seconds.
  • make docker-run also turns on the built-in site and playground (RESTACT_BUILTIN_SITE=1) and the example content (RESTACT_EXAMPLES=1); the image itself seeds no example content.

For a lighter image with no JavaScript or Python tier, use make docker-build-core. It builds faster and serves only compiled verbs.

Pass any configuration variable with docker run -e. Run with Docker covers volumes, compose and process isolation.

Check the install

Section titled “Check the install”

With the server running, discovery lists what this build supports:

Look for text/javascript in the languages line (service.acceptedSourceLanguages in the raw document, which curl localhost:8080/.well-known/restact also returns). If it is missing, the JavaScript runner was not built or was not found; for a release archive, check that share/restactd/runners/ sits next to bin/; for a source build, rerun make build-js-runner and restart from the repository root.

Caution

With no authentication configured, every caller is anonymous and may deploy, replace or delete any verb. The default bind address keeps that to your machine. Read Add authentication and the production checklist before you expose a host.
