Capabilities and budgets

A verb can reach only what it imports, and it can spend only what its budget allows. This page explains both limits and what a caller sees when one is hit.

Capabilities

Section titled “Capabilities”

Every verb is a WebAssembly component built for a WIT world. The world lists the host interfaces the component imports, and the host links nothing else. No world offers sockets, and the WASI filesystem interface is linked with no directories, so a verb has no way to read a file or open a connection. At upload the host inspects the component’s imports and refuses any it does not offer: a component importing wasi:sockets is rejected with 403 disallowed-import.

The interfaces live in wit/. Some are ambient, granted to every verb that imports them. Others are gated, meaning the host links them only for verbs that import them and then checks each call.

InterfaceKindWhat it lets a verb do
host (log)ambientWrite a structured log record. Rate limited per tenant.
identityambientRead the caller: subject, is-anonymous, roles, scopes, groups, claim. It grants no authority the verb does not already have.
objectgatedRead and write the data of the object the verb is bound to, read and write other objects by path, list an object’s shape, read binary values, run a paged query, and use set-at-if for compare-and-swap writes.
composegatedCall another verb by route.
eventgatedPublish an event to a topic.
llmgatedRequest one bounded text completion through a connector object, a stored record that names the endpoint and a secret. The model credential never reaches the verb.

Outbound HTTP follows the same rule. A verb has no network access of its own. The only outbound paths are host-mediated calls, such as the llm interface, where the host holds the credential, checks the destination against an operator allowlist and sends the request itself. See Outbound calls and secrets.

Which worlds exist, and which Cargo feature or language global exposes each interface, is in Authoring reference. Whether a given server offers an interface is advertised in discovery; see Discovery and optional features.

Gated does not mean broader than the caller

Section titled “Gated does not mean broader than the caller”

Gating decides whether a verb can call an interface at all. It does not widen what a call can do. The object capability applies the same read and write rules as GET and PUT /v1/<obj>, evaluated for the caller. A verb bound to someone else’s object reads and writes only what the caller could through the HTTP API. The write check for other objects is the same code the data plane uses. Function purity works the same way: a function that calls object.set, event.publish or an action is refused at runtime, and a function that declares a call to a deployed action is rejected at deploy with 400 invalid-call-graph.

Script verbs are in the same position, with one difference. The JavaScript and Python runners are single shared components, so their capability set is not a per-verb import list. The host enforces the same call graph, object rules and policy at runtime. See Language tiers.

Metering

Section titled “Metering”

Each invocation runs under three limits, enforced by Wasmtime:

ResourceMechanismWhen it runs out
CPUFuel, a deterministic instruction count429
Wall clockEpoch interruption, a deadline in milliseconds408
MemoryA cap on guest linear memory507

A verb that requests nothing gets 200,000,000 fuel units, 2 seconds of wall clock and 32 MiB of memory. It may request its own limits at deploy time with ?fuel=, ?wall_ms= and ?mem_mb=. The host clamps each request to an operator ceiling (RESTACT_MAX_VERB_FUEL, RESTACT_MAX_VERB_WALL_MS, RESTACT_MAX_VERB_MEMORY_MB; defaults 100000000000, 30000 and 512), so an upload cannot grant itself unbounded compute. The wall-clock limit is the real bound on CPU time. The same limits apply on both executor backends.

A JavaScript or Python verb is parsed again on every call, and the parse uses part of the run fuel before the verb’s own code starts. A large source can use up the default 200,000,000 units on loading alone and answer 429. Roughly, depending on the source, Python hits this at about 73 KB and JavaScript at about 185 KB; both are accepted at upload up to 256 KiB. Deploy a large source with a higher ?fuel=, up to the operator’s ceiling.

Beyond the per-invocation limits, operators can set per-tenant quotas on cumulative fuel, call count and stored bytes, optionally over a rolling window. A tenant over quota gets 429 and, for a windowed quota, an accurate Retry-After. See Configuration.

One budget under composition

Section titled “One budget under composition”

A verb in a composing world can call other verbs with compose.invoke. Each call must be listed in the calling verb’s declared call graph (?calls=a,b at deploy), and the host refuses an undeclared edge before anything runs. An action may also declare a pattern like *:audit, which names a verb of that name on any object. A function that declares a pattern is rejected at deploy with 400 invalid-call-graph.

The whole call tree draws on a single pool. The host debits the pool at each call boundary, so a tree of depth eight does not get eight budgets. The host also bounds depth (8) and fan-out (16 calls per frame) and detects cycles. A callee gets at most the caller’s authority, never more. Functions chain freely, and a function may call only functions.

What a caller sees

Section titled “What a caller sees”

Budget failures are ordinary HTTP errors with an RFC 9457 problem body.

SituationStatusrestact_code
Wrong method for the verb kind405method-not-allowed
Out of fuel, or shared budget exhausted429cpu-budget
Tenant quota exceeded429quota
Wall-clock deadline reached408timeout
Memory limit reached507memory-limit
Composition cycle, depth or fan-out limit508composition-cycle
Call to a verb outside the declared call graph403not-declared
A function attempting a side effect403forbidden-side-effect

The full list of codes is in Errors and status codes. Writes to the verb’s own object are merged only if the invocation succeeds, so a verb that runs out of budget leaves them unwritten. A write to another object with set-at commits at the call. With RESTACT_CONSISTENCY=atomic-invocation, the whole write set of an invocation, including those, commits together or not at all.
