The model in one page

restactd serves objects over HTTP. Each object has data and verbs: small programs you upload that run in a sandbox on the server. You read and write the data with ordinary GET and PUT, and you run a verb by naming it after the object with a colon.

The pieces

Section titled “The pieces”

An object is addressed by a path. A path has three forms:

A verb is either a function or an action. A function has no side effects and runs on GET, so responses can be cached. An action may change state and runs on POST. The host enforces the method: POST to a function or GET to an action returns 405. See Verbs, objects and routes.

A verb runs inside a WebAssembly sandbox with no authority except what it declares. It cannot open files or sockets. It can write a log line, and, if it imports them, read and write object data or call other verbs. See Capabilities and budgets.

By default a verb runs as the caller. Whatever the caller could not do through the HTTP API directly, the verb cannot do either; a verb deployed with runs_as=owner runs with its owner’s authority instead. The caller also pays: every invocation draws on a fuel, time and memory budget, and a tree of verbs calling verbs shares one. See Identity and authority.

A client learns what a server supports from the discovery document at /.well-known/restact instead of assuming. Optional features are advertised there, and a request for an optional behaviour the server lacks returns 501. A component that imports an interface the server does not offer is refused at upload with 403 disallowed-import. See Discovery and optional features.
