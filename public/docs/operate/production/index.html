Production checklist

Work through this list before a restactd host takes traffic from anyone you do not control. Each item says what to set and links to the page that explains it. The full variable list is in the configuration reference.

A host with no authentication configured is intentionally open: every caller is the same anonymous principal and owns every verb and object, so anyone can replace or delete anything. That is fine on localhost and wrong anywhere else.

Version

Section titled “Version”
  • Pin what you run. Deploy an exact release (VERSION from a release archive, or a container image by digest such as ghcr.io/stackumi/restactd@sha256:<digest>), not latest. Verify the download against checksums.txt first. See Install and Released images.
  • Confirm it. restactd --version prints the build line (version and commit, and the runner hashes a release build pins) without starting the server; the same line is the first thing a running host prints.

Network and identity

Section titled “Network and identity”
  • Bind deliberately. RESTACT_BIND defaults to 127.0.0.1:8080. Set 0.0.0.0:8080 (the Docker image already does) only when something in front of the host controls who can reach it. See Run with Docker.
  • List the host names clients use. A non-loopback bind makes RESTACT_ALLOWED_HOSTS mandatory; without it the host refuses to start. List exactly the public name and any in-network service name. Avoid * unless the proxy in front pins the Host header. See Allowed host names.
  • Terminate TLS in front. restactd speaks plain HTTP. Put a reverse proxy or load balancer in front that serves HTTPS and forwards the public Host. The single-node Compose example uses Caddy.
  • Configure authentication. Set RESTACT_JWT_SECRET (HS256 bearer tokens) or all three of RESTACT_OIDC_ISSUER, RESTACT_OIDC_JWKS_URL and RESTACT_OIDC_AUDIENCE. All three OIDC variables are required: setting only some of them (or any to an empty value) refuses boot and names what is missing. The JWKS URL must be https:// (plain http:// only to a loopback address). A blank RESTACT_JWT_SECRET, or a trusted sibling header without RESTACT_TRUSTED_IDENTITY_HEADER, also refuses boot. Confirm the boot line auth: OIDC/JWKS verification enabled …. Once any authentication is configured, anonymous callers cannot deploy or write (401); they can still read and invoke verbs that are public. See Authentication.
  • If a filtering proxy inspects request bodies, make it read them as restactd does. See Running behind a filtering proxy.
  • Use a trusted identity header only behind its proxy. RESTACT_TRUSTED_IDENTITY_HEADER takes the header’s value at face value with no signature check. Enable it only when restactd is reachable exclusively through the proxy that sets the header and strips any client-supplied copy. Prefer OIDC where you can. See Trusted-header mode.
  • OIDC egress. With OIDC, the host fetches the issuer’s JWKS over HTTPS. Allow outbound 443 to the issuer, or every token gets 401.
  • One identity source per subject namespace. If you enable both HS256 and OIDC, make sure their subjects cannot collide: they share one flat namespace.
  • Keep the built-in site off. RESTACT_BUILTIN_SITE is unset by default; leave it unset. Turning it on also serves repository documentation from the working directory.
  • CORS only if browsers call the API. RESTACT_CORS_ALLOW_ORIGIN is unset by default (same-origin only). Name exact origins; avoid *.

Who can define and reach what

Section titled “Who can define and reach what”
  • Object binding. On a host where more than one principal deploys verbs, leave RESTACT_OBJECT_BINDING at its default strict (or auto-create). Create the collection roots your wildcard-bound verbs use, with credentials, before users arrive. See Who may define a verb where.
  • Declare ACLs on object data. Undeclared object properties are public. Add $policy or per-property ACLs to anything that should not be world-readable or writable.
  • Keep the admin routes narrow. POST /admin/reset, /admin/checkpoint and /admin/reown do not exist until you name who may call them. Name a dedicated operator subject (sub:ops-1), never public, on an exposed host.
  • Scripting tiers. The JavaScript and Python tiers are on when their runner components are present. Remove the runner (or build the image with make docker-build-core) if you do not want callers to upload source verbs. Pin a runner’s hash with RESTACT_JS_RUNNER_SHA or RESTACT_PY_RUNNER_SHA so the host refuses a swapped file.

Isolation and limits

Section titled “Isolation and limits”
  • Process isolation for shared hosts. Set RESTACT_ISOLATION=process when untrusted tenants share the host. It needs a durable store. See Pick an executor.
  • Quotas with a window. Set RESTACT_QUOTA_FUEL and RESTACT_QUOTA_CALLS, and RESTACT_QUOTA_WINDOW_SECS (for example 86400) so the caps reset. Without the window they are lifetime totals. Add RESTACT_QUOTA_STORAGE_BYTES if callers can upload binary values. Set RESTACT_QUOTA_OBJECTS (for example 10000) when untrusted principals can write; without authentication every caller shares one count.
  • Review the concurrency and time limits. RESTACT_REQUEST_TIMEOUT_MS, RESTACT_MAX_INFLIGHT, RESTACT_MAX_WASM_INFLIGHT, RESTACT_WORKER_TIMEOUT_MS, and the per-verb ceilings RESTACT_MAX_VERB_FUEL, RESTACT_MAX_VERB_MEMORY_MB, RESTACT_MAX_VERB_WALL_MS. See Limits.
  • Egress interlock. If you set RESTACT_EGRESS_ALLOW, the host also needs the secrets mount and RESTACT_EGRESS_CONNECTOR_PREFIX or it refuses to start. A loopback entry in the allowlist is fatal unless RESTACT_EGRESS_ALLOW_LOOPBACK is set; do not set that in production. Like RESTACT_PG_ALLOW_PLAINTEXT, it takes 1, true, on or yes, and any other value refuses boot. Set the RESTACT_QUOTA_EGRESS_* caps. See Mediated egress and Troubleshooting.

Storage

Section titled “Storage”
  • Durable store. Set RESTACT_DATA_DIR (a volume, writable by the server’s user) or RESTACT_DATABASE_URL. Without either, every restart loses everything. See Pick a store.
  • PostgreSQL over TLS. Use sslmode=verify-full with a CA. Do not set RESTACT_PG_ALLOW_PLAINTEXT (it takes 1, true, on or yes; any other value refuses boot).
  • Postgres sizing for a cluster. max_connections at least N × (RESTACT_PG_POOL_SIZE + RESTACT_PG_LOCK_POOL_SIZE + a few), PgBouncer in session mode for large fleets. See PostgreSQL active-active.
  • Backups, and a tested restore. Filesystem: checkpoints copied off the machine. PostgreSQL: pg_dump or snapshots. See Backup and restore.

Monitoring

Section titled “Monitoring”
  • Probes. /healthz as liveness, /readyz as readiness. See Health and readiness.
  • Logs collected. Send stderr to your log system; set RESTACT_LOG_FORMAT=json for structured lines and RESTACT_ACCESS_LOG=1 for an access record. See Logs.
  • Metrics and traces if you use OpenTelemetry: build with --features otel and point OTEL_EXPORTER_OTLP_ENDPOINT at a collector on your own network. See OpenTelemetry.
  • Alerts on 429 and 5xx rates and /readyz failures, from your proxy or access log.

Running behind a filtering proxy

Section titled “Running behind a filtering proxy”

A WAF, API gateway or proxy rule that inspects request bodies has to read them the way restactd does. A filter that reads them differently can allow something restactd then treats as a different request. Rely on such a filter only for decisions restactd does not make itself; authorization stays with restactd.

  • A data-plane write body carries a media type. A non-empty PUT to /v1/<object> is JSON when its Content-Type is application/json, text/json or any +json type such as application/ld+json. Any other single type/subtype stores the bytes as an opaque value. The type is matched ignoring case and parameters. A non-empty body with no Content-Type, a blank or malformed one, or more than one Content-Type line is refused with 415 and writes nothing; a control character in the type gets 422. The exception is a path that an :update accessor verb serves, its own or an ancestor’s: the accessor receives the body unparsed and the media-type checks do not apply; the repeated-name check still runs first on a body with no type or a JSON type. Verb and management endpoints name their expected type in the HTTP API reference.
  • Names and strings are compared after escape decoding. A member name written with \u escapes is the same name as its plain spelling, so a rule that matches raw bytes sees something different from restactd.
  • A repeated member name is refused. A JSON body the host parses that repeats a name in any object, at any depth, gets 400. Do not depend on which copy a filter or another parser would pick.

Give the filter the same view of the request as the host: forward Content-Type unchanged, and do not rewrite or re-encode the body.
