Run with Docker

The repository’s Dockerfile builds restactd, the example verbs and both scripting-tier runners into a small non-root image. This page covers building it, running it, persisting data, and a single-node deployment with authentication and TLS.

Releases publish images to ghcr.io/stackumi/restactd (see Released images). You can also build the image from a checkout of the repository.

Build the image

Section titled “Build the image”

The first build compiles the host, the QuickJS runner (it downloads a WASI SDK and compiles QuickJS from C) and the Python runner, so expect a long build and a few GB of cache. Later builds reuse the layers.

TargetResult
make docker-buildHost, example verbs, JavaScript tier and Python tier.
make docker-build-coreHost and example verbs only (WITH_JS=false, WITH_PY=false). The image has no runner, so a JavaScript or Python upload (lang=text/javascript, lang=text/x-python) answers 415.
make docker-build-pgAdds the PostgreSQL backend (WITH_PG=true). Needed for active-active clusters. A released -full image already has it.

The Dockerfile also takes --build-arg WITH_OPENBAO=true to compile the OpenBao secrets backend. make help lists every target. IMAGE and TAG set the image name and tag (TAG defaults to dev). This page uses IMAGE=restactd; pass the same IMAGE to the other targets, or run docker build -t restactd:dev . yourself.

Released images

Section titled “Released images”

Releases publish two images to ghcr.io/stackumi/restactd, built from the release binaries rather than from source.

FlavourTagsContents
slimX.Y.Z, X.Y, latestWithout PostgreSQL. It refuses to start with RESTACT_DATABASE_URL set and names the -full image.
fullX.Y.Z-full, X.Y-full, fullAdds the PostgreSQL, OpenBao and OpenTelemetry features.

A release candidate gets only X.Y.Z-rc.N and X.Y.Z-rc.N-full. Both flavours run as uid 65532, keep data in /data, and install restactd at /usr/local/bin/restactd with the JavaScript and Python runners under /usr/local/share/restactd/runners/. They carry no /app directory, site or docs content.

Pin the image you deploy by digest, not by tag, so a re-pushed latest or X.Y cannot change what runs. The release notes list the digest of each image; the registry gives the same value:

gh attestation verify oci://ghcr.io/stackumi/restactd:$VERSION --repo stackumi/restactd --deny-self-hosted-runners checks an image’s build provenance.

Run it

Section titled “Run it”

docker run --rm restactd:dev --version prints the version and the commit the image was built from, then exits. An image built by make docker-build reports dev as the version; a release image reports its version number. make docker-build passes the commit; a hand-run docker build needs --build-arg RESTACT_BUILD_COMMIT=$(git rev-parse --short=12 HEAD), since the build context has no .git.

The image sets these variables, so it works without any:

VariableValue in the imageWhy
RESTACT_BIND0.0.0.0:8080A container must listen on all interfaces to be reachable.
RESTACT_DATA_DIR/dataThe filesystem store lives on the /data volume.
RESTACT_ALLOWED_HOSTSlocalhostThe host answers only to these Host names. See below.

The container runs as uid and gid 65532 on a distroless base with no shell. A fresh, empty named volume (-v restact-data:/data) inherits the right ownership, because Docker copies it only into an empty volume. A bind mount (-v ./data:/data), or a named volume that already holds files owned by another uid, must be owned by uid 65532, or the container refuses to start: an unwritable data directory is a fatal error, never a silent fallback to memory. Fix a bind mount with sudo chown -R 65532:65532 ./data and a named volume, which needs no shell in the image, with:

The image’s entrypoint is restactd, so its other commands run as docker run --rm <image> <command>. To snapshot a stopped host’s volume, or restore one, use a one-off container on the same volume while the server’s container is stopped; the data directory is locked while a server runs. The full procedure, including a running host, is in Backup and restore.

The image has a HEALTHCHECK that runs restactd healthcheck every 30 seconds. The command requests /healthz on the address in RESTACT_BIND (--ready requests /readyz instead), prints nothing on success and exits 1 with one line on stderr otherwise. The image carries no curl.

Caution

A host with no authentication configured is open: any caller can deploy, replace and delete verbs. docker run as shown is fine on your machine. Before you publish the port anywhere else, set RESTACT_JWT_SECRET (or OIDC) as in the example below.

Allowed host names

Section titled “Allowed host names”

The host rejects any request whose Host header is not localhost, 127.0.0.1, [::1] or listed in RESTACT_ALLOWED_HOSTS. This blocks DNS-rebinding attacks. Requests from another machine to http://my-server:8080 fail with 403 until you list the name:

List the public name your clients use and any in-network service name. /healthz and /readyz are exempt, so probes by IP keep working. See RESTACT_ALLOWED_HOSTS.

Configure with environment variables

Section titled “Configure with environment variables”

Pass any variable from the configuration reference with -e or --env-file. The built-in website and playground are off by default; make docker-run turns them on with RESTACT_BUILTIN_SITE=1 (plus RESTACT_EXAMPLES=1 for the example content), which you should leave off in production. The image itself seeds no example content.

make docker-run runs the image in the foreground on port PORT (default 127.0.0.1:8080) with the volume DATA_VOL; make docker-stop removes the container.

Compose files in the repository

Section titled “Compose files in the repository”

Both files are local demonstrations, not production templates.

docker-compose.postgres.yml

Section titled “docker-compose.postgres.yml”

Starts one PostgreSQL 16 container and two restactd nodes built with WITH_PG=true, both pointing at the same database through RESTACT_DATABASE_URL. Node A listens on localhost:8080 and node B on localhost:8081. A write, deploy, schedule or event on one node is visible on the other. The demo runs without authentication and sets RESTACT_PG_ALLOW_PLAINTEXT=1 because the stock postgres:16 image has no TLS; in production use sslmode=verify-full and drop that variable. down -v removes the database volume.

docker-compose.openbao.yml

Section titled “docker-compose.openbao.yml”

Starts a throwaway OpenBao server in dev mode, a one-shot container that writes a token file readable only by the restactd user, and one restactd node built with WITH_OPENBAO=true and pointed at it through RESTACT_SECRETS_URL and RESTACT_SECRETS_TOKEN_FILE. It exists to develop against the OpenBao secrets backend. The dev-mode server is unsealed, in-memory and uses a fixed root token, so never reuse it outside local development.
