Troubleshooting

Find the symptom, read the cause, apply the fix. Errors from the HTTP API are application/problem+json documents; the restact_code member names the exact cause, and the examples below show the real bodies. Startup failures print one fatal: or error: line to stderr and exit non-zero.

Startup

Section titled “Startup”

The system glibc is too old

Section titled “The system glibc is too old”

The Linux release binaries need glibc 2.28 or later. Run them on a newer distribution, or use the container image, which brings its own libc. ldd --version prints the glibc version of the machine.

macOS refuses to open the binary

Section titled “macOS refuses to open the binary”

The macOS binaries are unsigned and not notarized, so Gatekeeper reports that the developer cannot be verified or that the file is damaged. If the archive came through a browser, clear the quarantine flag on the unpacked directory and run it again:

Address already in use

Section titled “Address already in use”

Another process holds the port; the default is 127.0.0.1:8080. Find and stop it, or bind elsewhere:

Stop an old restactd by the port it listens on. Matching by process name also kills hosts you did not mean to stop.

Refuses to start on a non-loopback address

Section titled “Refuses to start on a non-loopback address”

A host bound beyond loopback must say which Host names it answers to. Set RESTACT_ALLOWED_HOSTS=restact.example.com. See Allowed host names.

Cannot open the data directory

Section titled “Cannot open the data directory”

The directory is not writable by the server’s user, or its deployments.json, registrations.json or format.json is corrupt. The host will not fall back to memory. In the Docker image the user is uid 65532, so the data directory must be owned by it: a fresh, empty named volume is, and a bind mount or a volume holding files from another uid needs the chown in Run it.

The data directory is in use

Section titled “The data directory is in use”

Another restactd holds the lock on <data-dir>/locks/data-dir.lock. Stop it, or point this host at its own directory. Under Docker, Kubernetes or systemd a restart policy retries until the old process has exited. A host killed with SIGKILL under RESTACT_ISOLATION=process leaves its workers holding the lock until they finish. See Filesystem.

If the lock file itself cannot be opened (wrong permissions, or a directory or symlink where the file should be), the host exits 1 with fatal: cannot open RESTACT_DATA_DIR=<dir>. It does not serve unlocked. Only a filesystem whose flock fails makes the host warn that the lock is not held, and then serve; under RESTACT_ISOLATION=process the cross-process lock probe refuses that filesystem and the host exits 1.

A directory with a RESTORE-IN-PROGRESS.json file also refuses to start, because an earlier restactd restore did not finish. Run restactd restore to complete or roll it back.

Refuses to start over an authentication setting

Section titled “Refuses to start over an authentication setting”

A set-but-unusable authentication setting stops the host before it serves, and the message names the variable. The cases:

  • Only some of RESTACT_OIDC_ISSUER, RESTACT_OIDC_JWKS_URL and RESTACT_OIDC_AUDIENCE are set, or any RESTACT_OIDC_* variable is set while one of the three is missing or blank. OIDC errors start with fatal: OIDC configuration:.
  • RESTACT_OIDC_JWKS_URL is a remote http:// URL or does not parse, RESTACT_OIDC_JWKS_TTL_SECS is not a whole number, or RESTACT_OIDC_JWT_HEADER is not a valid header name.
  • RESTACT_JWT_SECRET or RESTACT_TRUSTED_IDENTITY_HEADER is set but empty or blank.
  • RESTACT_TRUSTED_ROLES_HEADER, RESTACT_TRUSTED_SCOPES_HEADER or RESTACT_TRUSTED_GROUPS_HEADER is set without RESTACT_TRUSTED_IDENTITY_HEADER.
  • Any of these variables holds a value that is not valid UTF-8.

Set the missing value, or unset the variable you did not mean to set. The boolean switches RESTACT_PG_ALLOW_PLAINTEXT and RESTACT_EGRESS_ALLOW_LOOPBACK refuse boot too when they hold anything other than 1, true, on, yes, 0, false, off or no.

PostgreSQL refuses sslmode=disable

Section titled “PostgreSQL refuses sslmode=disable”

RESTACT_DATABASE_URL connections use TLS by default, and the modes disable, allow and prefer are refused at startup:

The fix is to use TLS (sslmode=require, or verify-full with a CA). For a throwaway local database only, set RESTACT_PG_ALLOW_PLAINTEXT=1. See PostgreSQL.

If instead the boot log says the database URL is set but the binary was built without the postgres feature, the host refuses to start rather than fall back to another store:

Use the restactd-full download or the -full image, build with --features postgres, or unset the variable.

Egress boot refusals

Section titled “Egress boot refusals”

Setting RESTACT_EGRESS_ALLOW turns on mediated outbound calls, and the host checks the surrounding configuration before it starts. Three messages, in the order you will meet them:

Configure the secrets mount: RESTACT_SECRETS_URL=file:/etc/restact/secrets.json and RESTACT_SECRETS_MOUNT=ws/{ws}/secrets/{name} (or an OpenBao URL on a build with the openbao feature). The secrets file must be mode 0600 in a directory that is not group- or world-writable, or the host reports fatal: cannot open RESTACT_SECRETS_URL=….

Set RESTACT_EGRESS_CONNECTOR_PREFIX=ws/{ws}/connectors.

Remove the loopback entry from the allowlist. RESTACT_EGRESS_ALLOW_LOOPBACK exists for test harnesses only.

Export is configured but nothing arrives

Section titled “Export is configured but nothing arrives”

The first boot line tells you:

The binary was built without --features otel. See OpenTelemetry.

Requests

Section titled “Requests”

403 on every request from another machine

Section titled “403 on every request from another machine”

The Host header names something not in RESTACT_ALLOWED_HOSTS. Add the name clients use, including the public name behind a proxy, and make the proxy forward the original Host. /healthz and /readyz are exempt.

401 on every write after enabling auth

Section titled “401 on every write after enabling auth”

Once any authentication is configured, anonymous callers cannot deploy, change verbs, or write object data. Send a bearer token:

If you do send a token and still get 401, the body says why:

Check that the token is signed with the host’s RESTACT_JWT_SECRET (the same value on every node of a cluster), has not expired, and, for OIDC, that the issuer, audience and JWKS URL match. Custom routes give a token that fails verification the same 401 as /v1; it is never served as anonymous.

409 object-binding when deploying a verb

Section titled “409 object-binding when deploying a verb”

With authentication on, RESTACT_OBJECT_BINDING defaults to strict: a verb can bind only to an object that already exists. Create the object first, then deploy:

For a wildcard route such as ws/{id}:action, create the collection root (ws) first. Property values on the data plane are typed, so {"a":1} is stored as a number; a value outside the rules (a number beyond ±(2^53−1) such as 1e21, nesting past 64 levels, a non-string $owner) is refused with 400 invalid-input.

Recovering from ancestor-claim

Section titled “Recovering from ancestor-claim”

With the ancestor-creation guard on, nobody may create an object above something another principal owns. The refusal is not retryable. The host’s operator log names the first foreign object or definition that blocked it (ancestor-claim: refused create of …). A store written before the guard can already hold such claims.

  1. List them with restactd audit ancestry (see Audit a store for ancestor claims). It runs beside a live server and changes nothing. Run it with the server’s environment and working directory, so it applies the same guard settings and finds the same bootstrap files; bootstrap state shows as host-bootstrap and is not counted (the host seeds example content only with RESTACT_EXAMPLES=1, and the audit follows the same variable).
  2. For a refused create, pick one remedy: use a different path; have the descendants’ owners delete first; or have the operator create the object directly (an RESTACT_ADMIN_REOWN subject sends X-Restact-Operator-Exempt: ancestor-claim), then reown it, without subtree, to the intended owner.
  3. For a claimed ancestor or an orphan definition in the audit, POST /admin/reown the ancestor to its rightful owner. With the server stopped, or no RESTACT_ADMIN_REOWN subject, run restactd reown instead (see Move ownership offline). An orphan definition is reowned with subtree: true, or by reowning its anchor path, which also selects the deployments anchored there. Reown pauses the object’s lifecycle hooks and withdraws runs-as-owner.
  4. If a same-level pattern pair is listed, accept the new winner (the leftmost literal) or delete one of the two verbs.

A deleted root has to be re-created before its owner’s descendants can be reached again. The only exemption source is RESTACT_ADMIN_REOWN. A writer who owns 10,000 or more objects or verb definitions at or below an absent path is always refused at that path, and the operator log says check limit reached; the operator creates the path, then reowns it (not subtree) to the writer.

500 verb-unlinkable when invoking a verb

Section titled “500 verb-unlinkable when invoking a verb”

The stored component imports an interface this host no longer provides, or provides with a different signature, usually after a host upgrade. The verb never ran. The host also writes one line per verb to stderr, verb-unlinkable: route=<route> import=<import>: at startup when the stored import names show a removed interface, and on the first call when only linking shows a changed signature. The verb stays in discovery. Redeploy it built against this host, or delete it.

405 when invoking a verb

Section titled “405 when invoking a verb”

A function verb is invoked with GET, an action with POST. Match the method to the verb’s kind.

415 on a JavaScript or Python upload

Section titled “415 on a JavaScript or Python upload”

The host started without the scripting tier because the runner component was not found. With RESTACT_EXAMPLES=1 you will also see warnings like could not bootstrap JS example 'hello:greet': unsupported source language: text/javascript. Build the runner and point the host at it:

From a release archive, keep share/restactd/runners/ next to bin/ (see Install); a restactd copied out on its own has no runners and starts without the scripting tiers. An installed binary (one whose directory has a sibling share/restactd/) looks only under share/restactd/runners/ and never in its working directory. A binary run from a source checkout looks at examples/js-runner/target/wasm32-wasip2/release/js_runner.wasm and examples/py-runner/…/py_runner.wasm relative to its working directory. RESTACT_JS_RUNNER_WASM and RESTACT_PY_RUNNER_WASM override the paths; the first boot line (layout: installed (share …) or layout: checkout (cwd …)) says which rule applied, and a javascript: or python: line says what happened to each tier. The Docker image includes both unless built with make docker-build-core.

A tier can also be off because a runner was refused. If the log says a runner’s sha256 does not match its pin, the file at the path is not the one the pin names. A release build pins the runners it shipped with, so a replaced file under share/restactd/runners/ leaves the tier off: restore the shipped file, or set both RESTACT_JS_RUNNER_WASM (or RESTACT_PY_RUNNER_WASM) and the matching RESTACT_JS_RUNNER_SHA (or RESTACT_PY_RUNNER_SHA) to run a different runner. The warning reads:

A refused or unreadable runner withdraws the tier: discovery drops the language and a new deploy returns 415, while verbs already deployed keep running with the runner they were deployed with. That holds on the filesystem store and on PostgreSQL alike. The boot line is javascript: off (<reason>) when the tier is gone and javascript: stored runner kept (<reason>) only when no pin is set, the default file is absent or cannot be registered, and a stored runner still serves it. If the layout line reads checkout for a binary you installed, the executable could not be resolved at start (for example it was replaced while running); the warning above the line gives the reason, and restarting the process fixes it.

422 invalid-source on a JavaScript or Python upload

Section titled “422 invalid-source on a JavaScript or Python upload”

The script failed the syntax check at deploy time:

The detail carries the interpreter’s message and position. Fix the script and upload again. Runtime errors appear later, at invocation, as script-error.

501 feature not supported

Section titled “501 feature not supported”

The request needs a feature this host has turned off or does not have. The detail names the switch. Check what the host advertises before you rely on a feature:

If the feature is missing from the list, the host does not support it. If it is disabled by an environment variable the message names, remove that variable.

curl changes the {id} in a route

Section titled “curl changes the {id} in a route”

This deploys the verb as things/id:poke. curl treats {id} as a glob set and sends only id. The same happens when you call GET /v1/things/{id}:poke. Pass -g (globoff), or URL-encode the braces as %7B and %7D:

Remove the wrongly named verb with DELETE /v1/things/id:poke/code (answers 204), then deploy again with -g.

Deploy validation errors

Section titled “Deploy validation errors”

POST /v1/modules rejects a bad upload with a specific code:

Statusrestact_codeCause
400invalid-componentThe body is not a WebAssembly component (not a valid WebAssembly component: failed to parse WebAssembly module), or it lacks the invoke export of the verb world (the detail names the export). Build with cargo component build --release, or with the SDK’s cargo build --target wasm32-wasip2.
400invalid-inputA bad query parameter. Examples: exec must be 'public' or 'owner' (got 'nobody'); verb name 'b_x' is not a valid identifier (camelCase: [a-z][a-zA-Z0-9]*).
400(none)The verb query parameter is missing: Failed to deserialize query string: missing field verb“.
401unauthorizedAnonymous deploy on a host with auth configured.
403disallowed-importThe component imports something outside the sandbox, such as sockets or filesystem access beyond the allow-list, or an interface the host does not provide (the detail names it). Remove the import.
409object-bindingStrict binding and the object does not exist; see above.
412precondition-failedYou sent If-None-Match: * and the route already holds a verb.
413module-too-largeThe upload is over the 10 MiB module limit (module is N bytes; limit is 10485760). A request body over 12 MiB is refused earlier by the HTTP layer with a plain-text 413, not a problem document.
415unsupported-languageNo runtime for that source language; see above.
422invalid-sourceThe script has a syntax error.

Verb names are camelCase identifiers: letters and digits, starting with a lowercase letter, no underscores or hyphens.

Budget exhaustion

Section titled “Budget exhaustion”

Every invocation runs under fuel, wall-clock, memory and quota limits. The status and restact_code tell you which one:

Statusrestact_codeBody detailMeaning and fix
429cpu-budgetCPU budget exhaustedThe verb used its fuel. It was deployed with a low fuel=, or the verb needs more. Redeploy with a higher fuel=, up to RESTACT_MAX_VERB_FUEL. A composed call tree shares one budget (shared request compute budget exhausted).
429quotaper-tenant calls quota exhaustedThe caller used up their RESTACT_QUOTA_CALLS, RESTACT_QUOTA_FUEL or RESTACT_QUOTA_STORAGE_BYTES. Without RESTACT_QUOTA_WINDOW_SECS the cap is a lifetime total and the tenant stays blocked until the host restarts or the state is reset. Set a window so caps reset.
408timeoutwall-clock deadline exceededThe verb ran past its wall_ms (ceiling RESTACT_MAX_VERB_WALL_MS, default 30 seconds). The same code covers RESTACT_REQUEST_TIMEOUT_MS and a request body that arrives too slowly.
507memory-limitmemory limit exceededThe verb needed more than its mem_mb (ceiling RESTACT_MAX_VERB_MEMORY_MB, default 512).
508composition-cycleA verb called itself, or composition went too deep or too wide.
503unavailabletoo many concurrent event subscriptions, backing store is unreachableRESTACT_MAX_SSE_STREAMS reached, or /readyz reporting the store down. Retry later; the first case clears when a subscriber disconnects.

The per-verb limits are set at deploy time, with fuel, mem_mb and wall_ms query parameters on POST /v1/modules. The host clamps each to its ceiling, so a request above the ceiling is silently lowered, not refused. A real example, a verb deployed with fuel=1:
