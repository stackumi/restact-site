Observability

restactd writes logs, serves two health endpoints, and can export traces, metrics and logs over OpenTelemetry. This page covers each and what to alert on.

Logs

Section titled “Logs”

Log events go to stderr, one event per line. The boot summary (the store:, auth: and similar lines printed at startup) goes to stdout as plain text. Lines starting telemetry:, quota:, compile cache: and warning: go to stderr; the rest of the summary goes to stdout.

The first stdout line is the build: version, the commit it was built from (unknown when the build could not tell), target, profile and compiled features. restactd --version prints the same line and exits without starting anything, so quote it in bug reports.

Read the boot summary after every deployment: it states the store, the authentication mode, the quotas (quota: fuel=off calls=3 storage_bytes=off objects=off window=lifetime) and which optional surfaces are on. A warning: line there means the host started with a feature disabled, such as a missing runner component.

VariableEffect
RESTACT_LOGA tracing filter directive such as info, debug or restact.egress=debug. The default admits restactd’s own events at info and everything else at warn.
RESTACT_LOG_FORMAT=jsonOne JSON object per line with the keys ts, level, target, trace_id, span_id, message and fields.
RESTACT_ACCESS_LOG=1One access line per data-plane request, collection listing, SSE subscribe and token mint: method, path, subject and status. Object values are never logged.
RESTACT_ACCESS_LOG_INVOCATIONS=1With the access log on, also one line per verb invocation, with the :verb in the path.

With RESTACT_ACCESS_LOG_INVOCATIONS=1 also set, an invocation line looks like this in text mode, and the same fields appear under fields in JSON mode. It carries the method, path, subject and status, and no error code:

The access log is the complete per-route record. Metric route labels fold into an overflow series when a host has very many distinct routes, and the access line does not.

Values that callers control (paths, subjects, error text from a verb) are escaped before they are logged, so one request cannot forge a second log line. Verb log output is rate-limited per tenant and in total (RESTACT_GUEST_LOG_RATE_PER_SEC, RESTACT_GUEST_LOG_BURST, RESTACT_GUEST_LOG_CEILING_PER_SEC).

Health and readiness

Section titled “Health and readiness”
  • /healthz answers 200 with ok as long as the process is serving HTTP. It checks nothing else. Use it as the liveness probe.
  • /readyz answers 200 with ready when the backing store responds. On PostgreSQL it runs SELECT 1; if the database is unreachable it answers 503 and logs a warning. Memory and filesystem stores are always ready. Use it as the readiness probe so a node that lost its database is taken out of rotation.

Both are exempt from the RESTACT_ALLOWED_HOSTS check, so a probe that addresses the container by IP works. The Docker image’s built-in HEALTHCHECK uses /healthz.

Configuration

Section titled “Configuration”
VariableMeaning
OTEL_EXPORTER_OTLP_ENDPOINTBase URL of an OTLP collector that accepts http/json. The host appends /v1/traces, /v1/metrics and /v1/logs.
OTEL_EXPORTER_OTLP_TRACES_ENDPOINT, …_METRICS_ENDPOINT, …_LOGS_ENDPOINTA full URL for one signal, used as given.
OTEL_SDK_DISABLED=trueBuild no exporter, whatever else is set.
OTEL_SERVICE_NAME, OTEL_RESOURCE_ATTRIBUTESThe exported resource.
OTEL_TRACES_SAMPLERalways_on (default), always_off or traceidratio. Any other value is a fatal startup error when an exporter would be built.
OTEL_TRACES_SAMPLER_ARGThe ratio for traceidratio, a number from 0 to 1.

Rules the host enforces at startup, each as a fatal: line that names the variable:

  • OTEL_EXPORTER_OTLP_HEADERS (and its per-signal forms) must not be set. Credentials for your telemetry backend belong on the collector, not on the host.
  • An endpoint must be a plain http:// or https:// URL with no user name, password, query string or fragment.

http:// endpoints are plaintext. Point them at a collector on your own network. https:// is verified against the system CA certificates, so a slim container image needs ca-certificates. The standard HTTP_PROXY, HTTPS_PROXY and NO_PROXY variables apply. On shutdown the host flushes pending data and waits at most 2 seconds for the collector.

RESTACT_LOG controls stderr only. What is exported is fixed: the host’s own spans and log records at info and above, and never output from verbs.

Traces

Section titled “Traces”

The sampling decision is always made by the host. An incoming traceparent header from an authenticated caller becomes the parent of the request’s trace; from an anonymous caller it is recorded as a link only, so an unauthenticated client cannot choose your trace ids.

SpanCovers
http.serverOne HTTP request.
restact.authResolving the caller’s identity.
restact.policyAn authorization decision.
restact.invokeA verb invocation, including composed calls.
restact.workerA process-isolation worker.
restact.store.opA store operation, labeled with the backend.
restact.verb.deploy, restact.verb.property, restact.verb.rollbackManagement writes.
restact.object.deleteAn object delete and its cascade.
restact.egress.callA mediated outbound call.
restact.schedule.fire, restact.subscription.deliverTimer and subscription work.
restact.async.continuationThe background part of a 202 request; linked to the request that started it.
restact.mcp.call_toolA tool call through the /mcp facet.

Spans carry the caller’s subject as enduser.id.

Metrics

Section titled “Metrics”

Metrics are exported on the same endpoint settings. None of them carries a subject or a concrete object path.

InstrumentUse it to watch
http.server.request.duration, http.server.active_requestsLatency and load at the HTTP layer.
restact.invoke.duration, restact.invoke.fuel, restact.invoke.inflightVerb latency, compute used, and concurrency.
restact.worker.spawn.durationThe cost of process isolation.
restact.store.op.durationStore latency.
restact.events.subscribers, .published, .droppedEvent delivery, including dropped events.
restact.schedule.firedSchedule ticks.
restact.verb.lifecycleManagement operations on verbs: upload, code, policy, properties, rollback and delete.
restact.egress.calls, .duration, .bytesMediated outbound calls.
restact.llm.calls, .tokensCalls to configured model connectors.
restact.auth.decisions, restact.policy.decisionsAuthentication and authorization outcomes, including denials.
restact.guest.log.droppedVerb log lines dropped by the rate limiter.

The three instruments that carry a verb route label stop adding new label sets after 500; further sets fold into one point with otel.metric.overflow=true. Use the access log for per-route accounting on a host with many routes.

Metering signals

Section titled “Metering signals”

Each invocation is metered for fuel (compute), wall-clock time, memory and call count. These are enforced limits that also show up as status codes:

SignalStatusrestact_code
Per-verb fuel exhausted429cpu-budget
Per-tenant call, fuel or storage quota exhausted429quota
Wall-clock deadline408timeout
Memory limit507memory-limit
Composition depth, fan-out or cycle508composition-cycle

Count 429 and 507 responses in your proxy or from the access log to see which tenants hit limits; the restact_code is in the response body, not in the access line. See Troubleshooting for what each means and how to raise it.

What to alert on

Section titled “What to alert on”
  • /readyz failing for more than a few probe intervals.
  • A rising rate of 5xx, and of 429 with restact_code: quota.
  • restact.events.dropped above zero, and restact.guest.log.dropped climbing.
  • restact.store.op.duration and restact.worker.spawn.duration p99.
  • On PostgreSQL, the log line restact.pg.quota read_failed fail_open=true: quota enforcement is degraded while the database errors.
