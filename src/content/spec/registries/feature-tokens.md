# REST:ACT Feature Tokens registry

A *feature token* names an independently-advertised OPTIONAL feature. A conformant server publishes
the tokens it supports in the `service.features` array of its discovery document (draft
§Conformance, §Discovery; [ADR-0015](https://github.com/stackumi/restactd/blob/main/spec/decisions/0015-conformance-minimal-core.md)), and a client
**MUST NOT assume a feature the server has not advertised** — a token is the only sanctioned way to
learn that an optional behavior is present (`verb-reference-deployment` is the one registered
exception: absence is not proof there, and a client may attempt the create). This registry is the list of defined tokens; the
`featureToken` enum in [`openapi/x-restact-extension.schema.json`](https://github.com/stackumi/restactd/blob/main/openapi/x-restact-extension.schema.json)
is its machine-readable mirror.

- Registration policy: **Specification Required** (see [`README.md`](README.md)).
- A token is a lower-kebab-case string. Names are permanent: a token MUST NOT be reused for a
  different meaning, and a feature whose contract changes incompatibly takes a NEW token rather than
  redefining an existing one (the rule draft §wit-contract states for capability interfaces, applied
  to every optional feature).
- One token names one independently-observable behavior. Where a capability interface cannot **link**
  on a server that lacks a method, that method takes its own token even though it belongs to an
  already-tokened interface — a client must be able to gate *deployment*, not merely use, on it
  (the `object-cas` / `object-binary` / `verb-object-query` / `object-self-path` precedent).
- Status follows the sibling registries' convention: **`provisional`** = defined and in service
  (the reference host advertises it under its stated conditions); **`reserved`** = the name is held
  by a specification but is not in service on the reference host. Both are draft-era states; on
  publication the surviving entries become the initial IANA registry contents.

## Notes

- **Absence is meaningful.** A client that cannot find a token MUST take the unadvertised path, not
  probe for the behavior: a feature detected by trial is a feature that will be assumed on the next
  server that answers the probe by accident.
- **A token advertises a contract, not an implementation.** A server MAY advertise a token while
  omitting the header, field, or response it would produce in cases where it knows its answer would
  be incomplete, wherever the feature's own text says so (see draft §The read set of an invocation);
  what it MUST NOT do is emit a value that is wrong.
- Tokens whose behavior is a *capability method* are listed here and in
  [`capability-interfaces.md`](capability-interfaces.md) from opposite directions: this registry
  names what discovery advertises, that one names what a component imports.
